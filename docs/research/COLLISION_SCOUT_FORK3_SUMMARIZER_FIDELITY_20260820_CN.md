# fork 3（summarizer 保真度改造：F2 辅助重建 / F1 容量扩容 / F3 位置保持池化）撞车侦察报告

> 2026-08-20，按 AGENTS.md 协作协议规则 5（架构级臂开 GPU 前必出撞车侦察报告）。
> 拟开臂：针对 memory 向量"段首集中、段尾丢写"病灶（E86→E88→E89，见 §2）的三条消融臂——
> **F2** 训练期辅助 decoder 从压缩向量重建段内逐字节（推理拆除）；**F1** summarizer 加深/加宽；
> **F3** mean pool 换 4 个学习 query 的注意力池化（slot-attention 风格）。
> 侦察方式：WebSearch + FetchURL 实时核实（arXiv 为主），全部引文附编号/URL，存疑项逐条列 §8。
> 结论：**三臂均可开，无人撞车**；两条假阳性风险（F3 query 坍缩复现段首集中、F2 辅助 decoder
> explain-away）必须以探针剖面（E89 协议）为判读线并内置防坍缩设计，详见 §7。

## 1. 一句话结论

F2 的同构先例（压缩记忆 + 辅助重建：Compressive Transformer、ICAE）与反面判例（SAC 论证
"重建目标与下游错位"）都存在，但在"学习边界 byte 段 → 单向量 memory"语境、以**段内位置分辨
的保真剖面**为考场的格子上无人占位；F1 的理论文献（率失真/信息瓶颈/posterior collapse 族）
一致指向"512 维截面容量远未用尽、容量充足不等于会被使用"，纯扩容臂文献侧预期收益最弱；
F3 的机制件（PMA/Perceiver/Slot Attention）全是标准件无新颖性可挂，但其已知失败模式
slot collapse（槽坍缩）与我方病灶同源，是头号内险。**byte 压缩 LM 谱系里"尾部信息丢失"
只有解码侧 patch lag（2605.09630）与 SSM 侧 chunk 细节糊化（2608.02032）两个最近邻，
编码侧位置分辨保真剖面无人报告——E86/E89 的逐 slot 探针本身就是空档贡献。**

## 2. 病灶复述（侦察问题形式化）

- E86 附录 A 逐 slot 剖面：接口向量可读信息从 slot0 的 +0.126 衰减到 slot18-31 的
  ~0.02-0.05，信息密度集中段首。
- E88：段尾丢失定位 = summarizer 压缩一级（头尾比 5.15× 在 memory 行已成形，下游近似
  保形传递）；段首 4 字节线性可解码率（real−garbage Δacc）~0.44-0.57，段尾 16 字节只剩
  ~0.07-0.10。
- E89：非线性探针（2 层 MLP）对线性探针段尾超额 = −0.002（0.0981 vs 0.1003）——段尾信息
  是**编码时没写进去**，不是读不出。靶子锁定 summarizer 编码目标/容量，读出接口形态在
  本维度无罪。

侦察问题因此形式化为三条：① 辅助重建监督能不能把段尾"逼进"瓶颈（F2）？② 瓶颈/编码器
扩容能不能提高写入率（F1）？③ 池化保序能不能让段尾不被洗成袋装（F3）？

### 3.2 近 12 个月走向

上下文压缩界出现明确的"**去重建化**"信号：SAC（2510.08907，2025-10 → ICLR 2026）以
anchor token 取代随机初始化压缩 token 并公开质疑 AE 必要性；其对 500xCompressor 的复现
部分推翻了 ICAE 的"AE+LM 更好"消融——**AE 之争在 2025-2026 是活议题，无定论**。自监督
视觉界 JEPA 系继续压重建（2604.13518 等综述层确认其为主流叙事）。codec/tokenizer 界重建
仍是主目标（2512.21913）。**三方张力对我方的含义：重建辅助是否有效取决于"重建目标与
终考目标是否同族"——我方终考含段内重建/续写字节，与 F2 辅助目标同族，SAC 的错位论证
不直接适用，但必须在预注册里显式回应。**

### 3.3 差异点一句话

**F2 是在"学习边界 byte 段 → 单向量 memory"语境、以段内逐 slot 可解码剖面为判据的辅助
重建——Compressive Transformer/ICAE 只看总重建与下游任务，SAC 争论的是 QA 对齐，JEPA
防的是坍缩，无人在段内位置维度诊断或施治"尾部字节没写进瓶颈"。**

### 3.4 可直接借的设计细节

1. **辅助 decoder 容量封顶**（MAE 2111.06377 原则 + posterior collapse 1511.06349 教训）：
   建议 ≤2 层、小 hidden，必要时对可预测字节掩码——防止 decoder 用语言先验 explain-away
   （解释掉）段尾字节。
2. Compressive Transformer 的 attn-recon 损失形态（注意力权重重建而非全文重建）可作
   轻量变体。
3. ICAE 的 AE+LM 联合配比经验：AE 半量 + LM 半量的数据划分（SAC §4.1 复现口径）。
4. 判读线沿用 E89 探针协议（线性+非线性双臂、real−garbage Δacc、逐 slot 剖面），
   **不以 aux recon loss 本身为成功指标**。
5. 信息保持评测可借 2503.19114 的口径（摘要级，用前复核）。

### 3.5 风险警告

1. **假阳性 A——辅助 decoder explain-away**：decoder 足够强时可用字节级 LM 先验猜中
   高可预测段尾字节，aux loss 下降但 memory 行探针读数原地踏步（posterior collapse 同构）。
   这是 F2 最可能的失败形态，判读必须走探针不走 loss。
2. **SAC 警示——重建与下游错位**：若 fork 3 终考是下游续写/补全而非段内重建，F2 可能把
   memory 挤向逐字节复印、牺牲语义可用性。缓解：辅助损失权重退火 + 推理拆除后下游回归
   测试列为验收门槛。
3. 梯度配比：辅助损失与主损失的梯度干涉未在本项目量过；文献侧无现成配比定律（ICAE
   1:1 数据半分是唯一可借锚点）。

### 4.2 近 12 个月走向

VQ 坍缩治理成熟化（EMA 更新/码本重置/STE 拉直/FSQ 免码本已成标准件，见 2411.16550、
huh23a、2309.15505）；latent 容量标度无新公开结论（Perceiver 线 2021-2022 后基本静止，
2026 年增量在 3D 神经场 [2403.12019](https://arxiv.org/abs/2403.12019) 类"latent 数涨→
重建质量涨但 runtime 线性涨"的朴素扫描）；率失真视角进入 LLM memory 综述层（2607.08032）。

### 4.3 差异点一句话

**文献扫的是瓶颈截面（latent 数/码本大小/向量维度），F1 改的是编码器表达力对"段内位置
分辨写入率"的影响——"加深加宽 encoder 能否修复尾部丢写"的位置分辨容量-保真曲线无人报告。**

### 4.4 可直接借的设计细节

1. 2411.16550 的坍缩诊断口径（有效占用率/位置分辨剖面类比）——若未来走离散化直接可用。
2. Perceiver 式 N×D 网格扫描作为实验矩阵画法；率失真曲线（保真 vs 参数量/FLOPs）作
   统一作图语言。
3. FSQ（2309.15505）作为未来离散化臂的免坍缩量化方案（登记备用）。

### 4.5 风险警告

1. **理论侧一致指向"容量不是约束"**：512 维截面对 25 字节段名义容量富余两个数量级；
   posterior collapse 族证明容量充足时模型仍可选择不写。E89 的判词（"没写进去"）更可能
   是**激励问题**（段尾字节对主损失贡献小）而非容量问题——**F1 单臂零收益是文献侧基准
   预期**，跑赢时须排查是优化/激励效应而非容量效应（防止把 F2/F3 的功劳记在 F1 头上）。
2. 扩容抬高计算并抬深梯度链，与 F2/F3 效应纠缠风险高——**必须单臂隔离 + 配套消融网格**。
3. 加深 summarizer 与 E83/E86 的"几何健康度→可训练性"教训有交互（深网络发散风险），
   沿用加固复训器口径。

### 5.2 近 12 个月走向

slot 系失败模式在 2026 年仍被反复形式化与修补（2605.02323、2606.30084、2505.20772），
说明"多 query 池化的坍缩/冗余"是活问题；句子向量界池化之争（mean vs CLS vs 加权）已
沉淀为工程常识（SGPT 后无新共识性工作）；集合保序的理论解（Janossy）无实用化进展。
**"池化丢位置"没有统一修法——多向量化（ColBERT 路线）是事实标准答案，与我方单向量
接口约束冲突，这正是 F3 的空档所在。**

### 5.3 差异点一句话

**F3 是在 byte 段（~25B）粒度、以段内逐 slot 可解码剖面为判据的保序池化——slot/PMA/
位置加权池化的已知应用都在图像对象或句子语义域，无人在"段内字节位置保真"考场做过
位置分辨的诊断与消融；我方还自带"slot collapse 机制与我方病灶同源"的独特对照价值。**

### 5.4 可直接借的设计细节

1. PMA（1810.00825）/Perceiver Resampler（2204.14198）的 learned-query 交叉注意力实现
   直接可抄。
2. **4 个 query 绑定相对位置先验**（query i 锚定段内第 i 四分位）——防 slot collapse 的
   最便宜手段；若嫌硬，可加 2605.02323 的 evidence depletion 式分工正则（二手，用前复核）。
3. **SGPT 位置加权 mean（2202.08904）列为零参数对照臂**——若加权 mean 已修掉头尾比，
   4-query 注意力即证伪为过度设计（此对照便宜且必做）。
4. 判读线沿用 E89 探针协议 + 逐 slot 剖面；slot 分工可视化（各 query 注意力图）列为
   过程指标（防坍缩监测）。

### 5.5 风险警告

1. **假阳性 B——query 坍缩复现段首集中**：2605.02323 的共享梯度机制在段内同样成立
   （段首字节梯度最大），4 个 query 无位置锚时可能全挤段首——F3 不加防坍缩设计则有
   高概率原地复现病灶。
2. **混淆变量**：4 query × 512 若 flatten/拼接使接口维度暗涨，赢球可能是 F1（容量）的
   功劳——预注册必须钉死输出口径（保持 512 单 vector 或显式声明维度变化并配容量对照）。
3. F3 只改"能不能分位置读"，不改"有没有激励写"——与 F2 正交互补，单臂天花板可能受限；
   预注册应含 F2×F3 联臂判读分支。

## 7. 开臂建议（三条臂文献空档判断）

| 臂 | 文献空档判断 | 撞没撞 | 开臂建议 |
|---|---|---|---|
| **F2 辅助重建** | 同构先例存在（Compressive Transformer attn-recon、ICAE AE+LM），反面判例存在（SAC），但"byte 段单向量 + 位置分辨判读"格无人占 | **没撞**（引 Compressive Transformer 为祖先，SAC 为警示） | **可开臂，带两条硬约束**：① 判读线=探针剖面（E89 协议），禁止以 aux loss 下降为成功；② 辅助 decoder 容量封顶 + 推理拆除后下游回归门槛 |
| **F1 容量扩容** | 理论侧（率失真/IB/posterior collapse 族）一致指向"容量非约束、激励才是"；位置分辨的编码器容量-保真曲线无人报告 | **没撞**，但**文献侧基准预期=单臂零收益** | **可开但降级为配套消融轴**（容量 × 机制网格），不作独立主臂；单臂跑赢时强制排查优化/激励混淆 |
| **F3 位置保持池化** | 机制件全占位（PMA/Perceiver/Slot Attention，无新颖性可挂）；"byte 段内位置保真考场"无人占 | **没撞**（新颖性只能挂考场与判据，不能挂机制） | **可开臂，必须内置防坍缩**（query 绑位置锚）+ SGPT 位置加权 mean 零参数对照臂；预注册钉死输出维度口径防 F1 混淆 |

**三臂均绿。最该警惕的一个风险**：F3 的 slot collapse 与 F2 的 decoder explain-away 都会
制造"**损失在降、病灶不动**"的假阳性——两者共用同一把锁：**判读线只能是探针剖面
（E89 协议），任何训练损失读数不得作为 fork 3 的成功证据**。
