## 3. 精读排程建议（26 项，交给 terra；不是本代理再派工）

每组都需在 `03_reading/<批次ID>/` 由协调者分配独立目录。优先顺序可随统一去重负责人调整；此处只提供建议，不代替调度。

### R-A：分离地址几何、值载荷与容量目标（7 项）

**001、003、015、033、050、051、052。**

必填：
1. 输入/键/值分布，任意查询或精确键查询，允许错误率、同时成功或平均成功、有限精度约束。
2. 存储规则是固定外积、在线差分、最优线性解还是任意学习算法；有没有独立的外部模式集合/目标字典。
3. 键维度、值维度、槽数和样本数分别如何进入容量公式；核几何与值相关性的作用能否独立识别。
4. 050 第一名检索阈值与列表检索条件：**k/n→r 并不是固定小 k 的候选列表保证**。若列表长度随样本数增长，后续精确验证成本可能吞掉收益。
5. 052 的原问题与竞争输出独立重采样的解耦问题，哪些是证明、哪些只是数值相似；不把近似模型容量写成原问题定理。
6. 051 的绝对化“正交必要”“容量增加无用”需红队对照 015/050/052，不能直接引用为一般事实。

一个可用于审查措辞的**独立代数核查，不是本轮论文证据**：若键矩阵 K 满列秩，存在伪逆 K†，线性映射 S=V K† 满足 SK=V；键无需两两正交。这只说明“非正交必不能精确存储”过强，不说明高负载、病态键、有限精度、在线外积写入都能成功。下一轮需把这些条件写清，避免以一个反例反向夸大无限容量。

### R-B：最接近多粒度＋来源细节访问（7 项）

**009、010、011、013、041、046、049。**

必填：
1. 原始 token、精确键值、压缩状态、路由统计分别保留多久；哪一步不可逆删除；是否需要 CPU/外存源副本。
2. 查询先读摘要还是直接读所有层级/槽？块分数是否由块均值、方差、最大相关 token 或另外学习的地址产生？
3. 路由选错块与选对块但值载荷损坏能否用不同对照区分；是否有路由召回率和条件于路由正确的读出正确率。
4. 是否存在“路由小摘要→原始来源下钻→找不到则扩搜”的完整机制，还是只有多分支融合。
5. 049 的“近恒定内存”和 64M passkey：显存、主存、外存、索引、预处理是否全计，信号密度是否随长度降低。
6. 011 内容路由状态锚与 013 每段矩路由的权重学习不同，不能只按“块摘要检索”合并为同一机制。

### R-C：写入、擦除、槽组织和协方差（7 项）

**005、006、007、014、017、019、030。**

必填：
1. 每个门/向量/矩阵作用轴、每次读写次序、旧关联保持项、重复键覆盖和近似键干扰。
2. 005 与 028 FG²-GDN+：从各自首发到最新版追出擦除/写入解耦的真正时间线和公式同异；028 是伴读，不新增优先计数。
3. 006 键侧读和值侧读：双侧差分是否仅增大更新秩？控制总参数、状态、每步 FLOPs 后是否仍有收益。
4. 007/014/017 分别控制槽总量、活动槽数、路由质量；固定状态不等于固定实用容量，稀疏访问不等于免费大内存。
5. 019/030 协方差是否提供键相关性的反干扰预条件；完整协方差和稳定近似的计算与低精度边界。
6. 030 摘要报告困惑度代价：原表位置、绝对值/相对值、匹配算力和匹配状态预算、是否能由再训练消除。

### R-D：反向结果与正交性校准（5 项）

**002、016、020、023、025。**

必填：
1. 002/023 理论模型类与当代 Delta/KDA 的包含关系；不要把门控卷积下界泛化成所有递归结构的下界。
2. 016 查询前置时为什么容量应足够；若关键是相关性表征出现太迟，增加记忆是否不能单独修复。
3. 020 对过去 token 的再优化依赖何种保留、批量、采样；训练/推理完整成本与因果可见性。
4. 025 的键和值头独立共享消融；它为“键值冗余不同”提供什么证据，又不能为“块地址和值必须解耦”提供什么证据。
5. 将 021 世界模型相反结果与 040 混合模型缓存手术作为伴读，核验结论域而不是把摘要强行并入普遍定律。

## 4. 竞争解释与后续判别问题（只提设计，不运行实验）

| 竞争解释 | 必须从全文找的鉴别证据 | 对后续研究取舍的影响 |
|---|---|---|
| 失败主要是有限位宽/有限状态容量 | 003/002 容量界，014/017 状态量扫描，同状态不同写入的对照 | 若主要随总状态量改善，应先与可扩状态、稀疏状态竞争，不能只归因压缩策略 |
| 失败主要是键几何/写入干扰 | 015 的核重叠分解，019/030 协方差和碰撞实验，006 双侧更新 | 若同容量下由键几何或更新修复，地址学习/反干扰更新可能优先于增加读出数量 |
| 路由摘要漏掉稀有强匹配 | 013 均值对均值＋方差、049 细粒度诱导块相关性，046 原始块选择 | 若路由召回率是瓶颈，可独立扩地址统计而不扩大值载荷 |
| 块载荷已经丢掉目标细节 | 010/041 精确缓存对比、046/049 回到细 token 的收益 | 路由更准也救不了值损坏，需要来源保留/回访或更高分辨率载荷 |

| “多槽收益”只是增加总内存/计算 | 007/014/017/022/029 的同参数、同状态、同活动算力与路由对照 | 若同预算收益消失，不应给槽数本身赋机制优越性 |

最便宜的后续概念对照建议（须由协调者决定是否立项，本轮不执行）：固定同一块和同一值载荷，仅交换平均键/矩统计/细粒度块打分；再固定路由，交换单摘要/多槽/回访原文。这样至少能将“找到地址”与“载荷保真”两类错误拆开。评价要同时报告路由召回、条件读出正确率、端到端准确率及源存储成本；单个最终分数不足归因。
