# 多粒度按需信息访问与选择性加工：初步研究构想（v0.1）

**英文工作名**：Multi-Granularity Adaptive Memory & Computation（暂定）  
**日期**：2026-11-08  
**状态**：开放式研究假说 / 调研交接草案；不是架构定案，也不是已被实验验证的新方法。

## 0. 一句话概述

探索一种使模型**同时保留不同粒度的信息表示及其可追溯关系，并由当前 Query 按需选择访问粒度、回访细节和计算深度**的架构。希望在相同总计算、存储和训练预算下，相比均匀压缩或统一加工，获得更好的长程细节检索、关系组合及下游任务表现。

核心并非“每条信息都必须完整重建”，而是**查询真正需要的信息能否被定位、读取，并实际影响最终预测**。

## 1. 问题背景与动机

1. **Full Attention** 具有灵活的任意 token 间交互能力，但长序列计算与 KV 存储成本高；当干扰项增长而相关项的打分优势不增长时，还可能存在注意力稀释风险。注意力稀释是条件性现象，不能作为 Full Attention 必然失效的定理。
2. **KV 压缩和递归状态**减少显存/带宽需求，但可能丢失未来查询所需的细节。对压缩 latent 的线性展开、Head-specific projection 或重新解码，不能凭空恢复从未进入 latent 的信息。
3. **统一粒度**隐含各信息对未来任务具有类似的重要性与精度需求；但事实查询、组合推理、语义概括、数字精确读取，所需要的粒度很不相同。
4. **统一加工深度**默认所有表示都应每层更新；Residual 已有恒等 Copy 路径，循环/条件计算允许仅更新部分活跃状态。
5. **元认知控制**要求模型低成本判断何时继续计算、是否需要更细节的信息，而不是在模型之外永久运行一个比主干还复杂的控制器。

来自 FLUED 的研究动机：单一 entropy/coding-rate 信号不足以稳定承担语义切分；表示可恢复、外加探针可读、部署读取与最终预测真正依赖内容，是不同证据层级。CBIU 曾探索通过严格反事实 On/Off 重算，把外部效用内化成控制监督；相关正负实验必须分别报告，不应把一个控制头的局部成功夸大为通用元认知能力。

## 2. 核心概念与边界

### 2.1 粒度不等于网络层数

建议至少区分四种相互关联、但不能等同的结构：

- **信息粒度（Resolution）**：字节/token、短片段、语义单元、事件/关系、组合概念等；层级可变、可重叠，不必是一棵严格树。
- **关系抽象纵深（Relation order）**：实体关系可以再次作为实体参与计算；与神经网络第几层没有天然一一对应关系。
- **表示加工深度（Processing depth）**：某条信息经历哪些 Transformer 变换，可通过跨层残差与选择性循环调整。
- **外部时间（World time）**：事实和关系随事件演化；应区分事件发生时间、写入时间、模型内部计算步数。

先前讨论的 `(对象 i, 对象 j, 关系递归层次 k, 外部时间 t)` 是帮助理解的概念坐标，**不是预设可以无损展开为固定形状四阶张量**。

### 2.2 三项互相独立的操作

- **Store**：保留当前内容、抽象表示以及必要的来源定位信息。
- **Read**：选择访问哪个抽象层、哪些节点、是否追溯原始细节。
- **Transform**：只对被选中的活动表示执行昂贵变换；其他表示可以保持 Copy，仍可能作为 K/V 被读取。

这种解耦优先是**职责和计算路径的解耦**，不预设必须拆成三个物理分离的大模块。

## 3. 一个开放的候选架构

```text
输入流 / 历史状态
       │
       ▼
[候选边界、语义单元或可变跨度分组]
       │
       ├────────────────────────► 细粒度信息 / 原始来源（可选保留）
       │                                     ▲
       ▼                                     │定位 / 回访
[多粒度表示构建：压缩、组合、关系提升]          │
       │                                     │
       ▼                                     │
[跨粒度索引 / 来源映射 / 时间版本] ────────────┘
       │
       ▼
Query + 当前状态 ─► 轻量路由 ─► 抽象读取 / 精细读取 / 回退
       │                                 │
       └─────────────────────────────────┘
                         ▼
           [Copy / Selective Transform]
                         │
                 [可选循环与反馈]
                         │
                     输出 / 更新
```

建议用 `M = {M⁰, M¹, …, Mᴸ}` 表示不同粒度的记忆集合。单个节点可包含：`latent、来源指针、覆盖范围、时间/版本、关系索引、可选质量元信息`。来源链接可为一对多、多对多，避免把所有表示强制成完美嵌套的树。

**关键开放选择**：最细粒度来源是始终驻留 KV、保存在低速 Memory、允许重新从输入计算，还是在预算下被丢弃？这将直接决定真实性能、信息可恢复边界与系统维护成本。

## 4. Query 条件化的访问决策

可采用一个分解式的候选形式：

\[
p(\ell,i\mid q,h)=p(\ell\mid q,h)\,p(i\mid \ell,q,h)
\]

这里 `ℓ` 表示粒度，`i` 表示该粒度上的候选节点。它只是方便研究的因子分解，不代表两级路由天然优于联合路由或扁平注意力。

访问可包含三种动作：

1. **Abstract-read**：先读取少量抽象表示，用于低成本范围判断、语义概括和候选定位。
2. **Drill-down**：对高概率相关、低置信度或高风险的节点，按需访问低粒度内容。
3. **Fallback / Explore**：当摘要无法可靠指出细节所在位置时，允许扩大搜索或访问原始内容，避免“摘要漏了什么，路由便永远找不到什么”的闭环失效。

要区分：**能读出信息、能利用该信息产生正确预测，以及预测对信息存在因果依赖**。不能只用 probe accuracy 判断系统成功。

## 5. 选择性加工（作为可选增强）

候选循环更新：

\[
h_i^{r+1}=h_i^r+g_i^r F_\theta(h_{\mathrm{active}}^r,\operatorname{Read}(q_i,M))
\]

- `r` 是内部循环索引，不是外部时间；`g=0` 是 Copy，`g>0` 时执行变换。
- 若要**真正节省 FLOPs**，需要按门控结果跳过计算，而不只是对已计算出的结果乘以 0。
- 非活跃实体仍可留作 K/V 来源；是否更新与是否可读取是不同决策。
- Looped/Recurrent Transformer、跨深度读取（Attention Residuals）、MoE/零计算专家可以作为备选扩展，**不应第一版全部拼装**。

## 6. 元认知与效用学习：候选而非必选模块

简单的低维状态 `z = φ(h, shared_features)` 可估计：目前信息是否足够、细节回访收益、继续加工收益、候选路由可靠性。

可参考 CBIU 的外部锚定协议：

\[
U_a = J(A\setminus\{a\}) - J(A)
\]

通过固定输入、参数、随机性与审计条件，执行真实 On/Off 干预，得到效用标签；以 stop-gradient 监督低成本预测器或 Router。**不能让当前策略直接修改自己的评价准则以获取虚高收益。**

初步多风险目标可考虑：

\[
J=\sum_j w_j r_j+\beta\max_j\Big[\frac{(r_j-\tau_j)_+}{s_j}\Big]
 + \lambda(C/B-1)_+ + \frac{c}{2}(C/B-1)_+^2
\]

其中加权部分保持整体优化压力，最坏违约部分突出当前主要风险；`τ、s、w、β` 需要外部标定，且这种混合仍不保证真正的硬约束。早期不必让模型自由调整风险权重，避免目标操纵。

元认知主张应从**可验证的自我校准和控制行为**定义，不能把 Router 或共享专家直接命名为元认知就视作完成。共享专家增加容量可能改善判断，也可能增加串行成本；可以考虑先路由后精评，但需要消融。

## 7. 最小可验证实验（MVP）

**优先验证“多粒度 + 按需回访”的净价值，不急于实现循环计算与 MoE。**

1. 固定一个可训练的小型宿主模型和预算，构造原始细粒度序列与多粒度摘要（最初可用固定窗口，后续才学习边界）。
2. 建立四组对照：`Flat Full Access`、`Uniform Compression`、`Hierarchy without Drill-down`、`Hierarchy + Query-Conditioned Drill-down`。另外加入 `Oracle Retrieval` 作为可达到上界的诊断基线。
3. 每组统一预训练数据、模型容量区间、实际 FLOPs、峰值/平均显存和存储预算；分别报告**质量-成本 Pareto 曲线**，不要单凭参数量匹配声称公平。
4. 任务先用可控合成数据：跨片段精确取值、多人/多实体属性归属、多跳关系组合、时间更新与旧事实失效、远距离例外信息、摘要无法提示的稀有细节。
5. 在固定任务协议下测试 `读取正确率`、`最终答案正确率`、`内容必要性（删除/替换相关证据）`、`路由漏召回率`、`真实 wall-clock`、`显存和 I/O`。
6. 若上述机制证明有益，再逐步加入 `学习式边界`、`跨深度读取`、`Copy/Transform`、`Looped Computation`、`CBIU-style utility head`，每次只引入一个主要机制，留独立对照。

## 8. 预注册假设与可能的证伪

| 编号 | 预测 | 可能削弱/否定的结果 |
|---|---|---|
| H1 多粒度访问 | 在固定总预算下，对既需要全局概括又需要稀有细节的任务，优于同等成本的均匀压缩 | 质量-成本前沿不改善，或提升完全来自额外预算 |
| H2 来源回访 | 相比只保留高层摘要，Drill-down 可改善稀有精确细节题 | Oracle 回访有效但学习路由无效，说明路由是主要瓶颈；Oracle 也无效则需检查表示/任务 |
| H3 路由价值 | 低成本路由开销小于节省的高成本读取/加工 | 路由和 I/O 开销抵消 FLOPs 节省；高层漏召回形成系统性失败 |
| H4 内部效用 | CBIU 式监督可提高计算动作对真实边际收益的排序和校准 | 换任务/预算后 AUC、相关性、校准崩溃；仅训练分布有效 |
| H5 选择性加工 | 按需 Copy/Transform 在相同实际延迟下改善质量-成本前沿 | 懒更新造成错误累积，重新激活开销或依赖关系传播大于收益 |

**注意**：这些是研究预测而非结论；真正预注册前还要补足具体数据分布、模型规模、统计检验、种子数量及通过阈值。不要事后改动原定指标来把探索性结果当成确认性证据。

## 9. 最应警惕的失败模式

- **摘要失明**：高层摘要抹掉了识别低层重要证据所需的线索。
- **可恢复 ≠ 可消费**：探针可以恢复信息，但部署 Query 并不实际依赖它；需要严格干预。
- **抽象层次不是真语义层次**：不同尺度只是更多压缩窗口，缺乏关系组合能力。
- **非局部依赖**：一次写入/切分/跳算改变多个后续动作的效用，单独 On/Off 不可加。
- **错误自我评估**：低维控制表示过度自信，系统反复选择错误粒度或错误终止。
- **过度工程化**：索引、来源回访和循环控制引入额外数据结构与通信，实际速度不升反降。
- **实验混淆**：同时修改 Tokenizer、记忆、注意力、Router 和 Loss，无法判定真正的增益来源。

## 10. 调研路线（按机制而非模型名分组）

1. **序列压缩 + 细节回访**：DeepSeek V4 的 CSA/HCA，DeepSeek V4.1 的 CSA2/CED，MiTA 的 compress-and-route；重点看压缩率、路由漏召回、KV 生命周期和部署开销。
2. **记忆层级与来源索引**：Hierarchical Memory Transformer、Compressive Transformer、Memorizing Transformers；重点看多层记忆是否保留可追溯的原始信息。
3. **跨深度表示读取**：Attention Residuals 与 Block AttnRes；重点看跨层混合与抽象粒度之间是否真的存在对应关系。
4. **按需计算与状态重入**：Mixture-of-Depths、Universal Transformer、Looped / Recurrent Transformers、零计算专家；重点看是否能真正跳算及重新激活。
5. **因果效用与控制**：CBIU 的严格 On/Off、Value of Computation、Adaptive Computation Time、元认知校准；重点看效用标签是否可以低成本外推。

## 11. 当前仍须由研究者决定的设计卡点

1. 优先优化**长程精确访问**，还是**跨层组合推理**？两者评价协议不同。
2. 多粒度结构是固定 chunk、学习边界、关系图，还是允许重叠的混合结构？
3. 原始信息在压缩后继续保留多长时间？是驻留、外置、回放重算，还是按需淘汰？
4. 路由是否具有可校准的“不知道”，并能触发宽搜索/回退？
5. 先做独立的可训练原型，还是嫁接到 FLUED？两条路线的归因和工程代价差异显著。

**当前建议**：以“固定粒度多级摘要 + 保留来源指针 + Query 按需回访”为最小可证伪原型；其余机制作为候选增强保留，不在本轮预设最终架构。
