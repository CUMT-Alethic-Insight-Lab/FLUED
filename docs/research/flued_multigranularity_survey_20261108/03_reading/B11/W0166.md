# W0166｜RetrievalAttention: Accelerating Long-Context LLM Inference via Vector Retrieval

- Di Liu、Meng Chen、Baotong Lu、Huiqiang Jiang 等，2024；[arXiv:2409.10516v3 PDF](https://arxiv.org/pdf/2409.10516v3)，2024-12-31。**FULL**：读PDF第1–10页、附录A–C/E–G及相应表2–11；图读图注/文字，未逐点数字化。未核代码或复现。
- **查询分布索引**：§2.4、§3.2及图4，预填充已有query与key做精确KNN连接，再按共享query将边投影到key图，消掉索引中的query向量；解码时当前query搜图。构图可用完整提示的prefill query（提示全段在此可见），不需要未来生成query；无额外模型训练。每查询头一个索引，组查询注意力各头分布不同，组内KV共享底层副本（附录C）。
- **存取**：§3.3初始128及最近512 token保GPU，其余原始KV在CPU向量库；CPU搜出逐token KV并计算部分注意力，GPU静态部分并行计算，两者用softmax分母加权合并（附录B式4–5），非必须把所有命中载荷搬回GPU。后续查询可重搜，未来生成key及动态索引维护的具体成本未闭合。ANN召回是与精确内积近邻交集，不是必要事实召回；无在线遗漏证书。
- **结果与失败**：图2，同一100K prompt的top-1000以首query固定时注意力质量由89%降到71%；图6在该实验以扫描1–3%达到>0.95 Recall@100，仅对近邻。表2 Llama-3 128K复杂KV retrieval：全注意17.5，精确Flat 14.5、本文14.0（各2K动态KV）；70B表11全注意35、Flat24、本文23.5、Quest13，不可说与全注意无损。附录F按层调预算KV retrieval 14.5→16.0但En.QA 8.7→8.5。
- **成本**：表4/5：4090+10核CPU、128K、批1，每token总0.188秒，其中搜索0.064、注意力0.081、其他0.043；预填充与构索引在§3开始明确预先完成，不是整请求全账。附录A.4在80GB A100与大CPU内存条件，128K vLLM全KV 0.033秒/词、本文0.155秒，足量显存时不胜dense；1M用1.72TB内存主机。每头索引字节、构建/增量更新与冷缓存尾延迟未报完整。
- **草案差异**：是全源KV存活+查询专用索引的平层内部读取，而不是多层可变语义粒度或校准回退；构索引用已见prompt query，而非未来任务标签。建议同源、同硬件和完整构建/多查询摊销对照Quest及强平层精确检索。
