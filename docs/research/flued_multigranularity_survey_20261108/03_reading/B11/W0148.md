# W0148｜Quest: Query-Aware Sparsity for Efficient Long-Context LLM Inference

- Jiaming Tang、Yilong Zhao、Kan Zhu、Guangxuan Xiao、Baris Kasikci、Song Han，2024；[arXiv:2406.10774v2 PDF](https://arxiv.org/pdf/2406.10774v2)，2024-08-26（无版本目录入口经提交史锁v2）。**FULL**：实际读PDF第1–9页正文、表1及图注；第10–11页参考文献；无论文内附录。曲线未逐点数字化。代码和实验未独立核验。
- **学习、可见性与地址**：§3.3–3.4、算法1，免新训练；按连续页留完整历史KV，额外维护每页每维key最小/最大值；每个自回归当前query逐页算`U=Σᵢ max(qᵢminᵢ,qᵢmaxᵢ)`，选top-k页、加载页内全部token KV并注意力，前两层保持全量。未来输出不可见；被本次未选的页不等于永久淘汰，后续查询可重新选。
- **保证的精确含义**：U是页内任意单个未归一化点积的上界；不同维极值可能来自不同key，界可很松。top-k按上界排名不保证真实高分key或必要事实进入；即便所有单项得分低，大量低分项仍可合成重要总softmax质量。图3 oracle是全注意得分派生的诊断，并非部署时可用。图4的top-10注意力召回不是事实召回或答案因果依赖。
- **实测与反例**：表1 10K密钥任务，预算32/64/512时Quest 65%/99%/100%；100K预算1024为96%，2048为100%，故不能写1024完美。历史驱逐基线与保留全部KV的权限不同；H2O在100K及LongBench从解码才收集历史分数，影响比较。§4.3图9/10：32K、2048预算，注意力7.03倍，Ada 6000单批解码每token量化权重2.23倍、FP16 1.74倍；不含采样/prefill。相同精度下竞品速度是FlashInfer代理而非完整竞品实现。
- **资源与差异**：§3.5页大小S、长度L、K页估算读取比例`1/S+KS/L`，另存每页两条元数据；原始KV仍在GPU内存，非总存储压缩。原文64K例称“4K pages”与8倍算术不一致：若字面4096页×16=全量，不可能8倍；可能意指4K token，但不得代作者定稿。无跨查询校准漏召回、源版本或跨设备回访成本。草案若做可回访需对照这个平层query页选择及oracle，不能把保留源等同检测遗漏。
