# W0434｜CacheGen: KV Cache Compression and Streaming for Fast LLM Serving

**FULL（v6正文及关键附录A–E阅读；未核代码/复现）**。Yuhan Liu、Hanchen Li、Yihua Cheng等，SIGCOMM 2024；[arXiv 2310.07240v6](https://arxiv.org/html/2310.07240v6)，[v6 PDF](https://arxiv.org/pdf/2310.07240v6)。HTML在附录A截断，续用PDF转换阅读B–E；图表数值以对应图表/文字为准。

## 编码、地址与权限
- §5.1–5.2：先按连续10 token成组，首项作为anchor，其余记与anchor的差；浅层比深层保留更多量化精度，anchor使用8位；再按层/通道分布算术编码。算术编码对**量化后的符号**无损，不代表恢复原浮点KV无损；8位也只是论文所测任务的近乎无损。全上下文先prefill，再沿token切块，块内离线制作多份不同量化位流；无参数梯度训练，离线统计分布和系统策略而非学习语义压缩器。
- §5.3、附录C：流式块默认约1.5K token；用前一块吞吐预测后续，选满足首字延迟目标且失真最小配置；太慢时发送原文并依赖此前收到/解码的KV重算当前块。网络变化一块后才响应，目标并非硬保证。生成问题发生前已编码，压缩不能使用该问题/答案；决策是传输块及量化等级，不是查询条件选择语义内容。
- §6存储字典为`chunk_id → encoded_KV`；文中未详细规定key是否包含完整前缀、模型权重/位置/精度与版本，不能假设任意拼块严格等价。回退需要对应原文、生成器和所需前缀KV；受损先前KV会影响随后重算，不能声称完全原样恢复。

## 对照、结果、系统成本
- §7.1–7.2：四A40，662段1.4K–16K token，Mistral-7B、Llama-34B/70B。3Gbps下相对文本prefill首字延迟3.1–4.7倍、相对统一量化3.2–3.7倍更快；相近输出质量KV体积较统一量化小3.5–4.3倍。分别是对应实验，不是全部冷热访问总成本。§7.2理想化H2O在离线编码时使用问题的query张量，权限不同；附录B同理为Scissorhands提供离线理想信息。
- §7.3：小于1K token时自动回退文本；§9指出更强GPU/低带宽、低复用动态搜索、高自由文本任务可能缩小收益。§7.4模拟0.1–10Gbps轨迹，1秒SLO违规81%降至8%，非绝对保障。
- §7.5图14与附录E：编码示例约200ms，多份压缩版本总存储约与量化基线同量级；8.5K token、Llama-13B多版本约5GB，文中按当时价格粗估每月150次以上复用可能节省费用，不能外推现价或含全成本。源文本、索引、全精度活跃张量、各bitstream副本、训练/构建、初问prefill、维护、搬运和尾延迟必须分别计；论文未完整合账。
