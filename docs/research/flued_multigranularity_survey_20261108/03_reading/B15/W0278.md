# W0278｜What Sets the Serving Speed of Looped Language Models?

- **FULL**：Dezhen Lu、Runguo Li、Zixiang Ni、Yuchen Tang、Xingquan Kong、Jiaxing Yang、Jiarui Guo、Lingxiang Gao，2026，[arXiv 2611.05150v1](https://arxiv.org/html/2611.05150v1)，2026-11-03。浏览器完整续读正文§1–8、表1–4、附录A–D及各组件表至结尾。代码和实验未独立运行，等价性证明未独立验证。
- **对象与方法**：§2–4 Ouro-1.4B为24层×4循环，固定深度4；Huginn-0125为4层递归块×32，层间同深KV独立。重排KV活槽、融合小核、调度、前缀缓存及预填充分离；并非学习来源粒度或训练路由。输入位置、层、循环深度是KV地址，缓存保存派生KV，生命周期/完整源及淘汰全账不在问题设置中。查询仅依赖自回归前缀，未展示依据未来答案读取。
- **精确性分级**：表1及§4：r0同批位级一致；r1同每行运算但改批组成，GEMM可能改位；r2保持目标采样分布但随机数变；r3数值路径改变须质量检查。§4.2同时保持PyTorch归约顺序与内联PTX舍入栅栏（防舍入消失及乘加合并），仅对已测硬件、版本及形状的等价有证据；r0容量变化又可能间接改变批次。
- **瓶颈与结果**：§3 Ouro/GH200 batch 1每输出token 5689小核，24层×4循环；RTX 5090只融循环提交6→3次却0.99倍吞吐。§5.6精确融合1.11–1.59倍，1014/1014请求相同。Huginn每token预留5.41MB KV、实际写2.79MB；打包同池可容1.88倍token。表2同机基准上Ouro 1.65–2.15倍、Huginn 1.77–3.16倍，非质量匹配普通Transformer对照；基线是实验性vllm-rlt，未证明充分优化（附录B）。表3 16会话缓存额外1.16倍，59请求；重复长提示可能高估复用。
- **质量与反例**：§5.8 87题近似融合61或62正确、对应基线64，超过预定1百分点规则但置信区间含零；扩到1319题结果−0.15/+0.76个百分点，故小样本不证明精度下降。近似融合不更快且不逐位一致，作者未采用。位置噪声CPU冷热一致但GPU完整命中只有108/128一致；预填充打包Huginn −0.61个百分点，仅点估计过门，区间仍涵盖超1点下降。泊松真实请求Ouro 10次中2次异常终止，原因未定；预注册可持续请求率目标未达（§5.3、附录B）。
- **系统成本**：表4同GH200单机两GPU、并发32、2048输入，关闭对端错误处理的IPC 479 vs 143–147 token/s约3.3倍；保留错误处理时两次约3.1倍、一次205 token/s，三次平均约2.6倍。附录C表明TCP并非主瓶颈，较大在途预算消除轮询等待；关闭错误处理改变故障保障，不能视同公平同服务。报告TTFT/TPOT与部分p90，未形成冷源/索引、多机、p99完整账。附录A工件缺原始日志和历史运行脚本，不能据其完整复跑。
- **与草案差异/可用主张**：是循环服务优化而非细源回访、粒度选择；支持把数值等价、相同分布、质量近似和端到端速度分开核算，不能将特定引擎提升当循环架构的无条件净收益。
