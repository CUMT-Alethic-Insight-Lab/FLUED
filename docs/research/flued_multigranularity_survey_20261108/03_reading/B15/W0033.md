# W0033｜Reroute, Don’t Remove: Recoverable Visual Token Routing for Vision-Language Models

- **FULL**：Cheng-Yu Yang、Shao-Yuan Lo、Yu-Lun Liu，[arXiv 2606.12412v1](https://arxiv.org/html/2606.12412v1)，2026-06-10。前轮读正文§1–6及表1–4；本轮以[固定版PDF](https://arxiv.org/pdf/2606.12412v1)分段补读pp.16–27附录A–C、表5–15及图6–10文字说明到文末；示例图像未逐像素核验。未核代码、未复现实验。
- **学习/读取与粒度**：§3–4、式(1)–(2)：复用语言token对视觉token的注意力分数，无新训练路由器；每阶段选视觉token作完整注意力和FFN，未选token保留当前位置及旧隐藏状态不变，下一阶段从完整视觉token集合重新评分、可重入。文本始终活动；是同一视觉token粒度的延迟加工，不是将摘要展开为细源。当前文本问题参与评分；多阶段旧特征未作补算，重入后才更新。源删除、跨请求保留与淘汰未核。
- **对照/失败**：表1 HF格式LLaVA，64平均token下PDrop定位平均比例22.2%→34.0%；FastV 0.6%→0.6%，仍失败。官方Nüwa格式在192/128 token略降103.7→103.0%、90.9→90.3%，64时54.6→55.8%，并非所有基线单调提升。表3一般VQA在192 token的PDrop→Reroute GQA 59.2→58.9，TextVQA 46.9→57.4。比例是相对各自全token基线的平均，不是准确率百分点。
- **成本**：表4实际列64 token下PDrop 1.83 TFLOPs/49.7 MB KV，Reroute 1.99/51.6；FastV 1.60/41.5 vs 1.73/41.5。相同类别/平均token并非逐字节或算量完全相等。原文§4.3、§5.2及附录A–C未给完整驻留/重排、端到端延迟与尾延迟账；表4部分百分比与原始数值似有算术不一致，应优先引用实际数值，不擅改为勘误。附录A.2指出实验单张RTX 4090。
- **补充强反例/位置控制**：PDF附录C.2表15，Qwen3-VL-8B在视觉token减少66.7%时，PDrop相对全量平均比例69.5%，加Reroute降至57.2%；77.8%时38.9%→36.1%，88.9%时12.9%→19.1%。作者认为与模型特定视觉特征注入及手选调度有关，非所有骨干都获益。附录A.4表7，FastV保留原始位置索引比重排连续索引强得多（192 token RefCOCO A 27.8 vs 1.9）；比较需控制位置信息。附录表5–6显示FastV单次{3}对比Reroute {3,7,15,23}，不能将这组差异全归因重入而排除更多评分阶段。
- **与草案及W0032**：本作跨解码深度反复恢复旧视觉特征，W0032在入语言模型前一次文本导向回选加合并；都不是原始文本多级来源导航。对FLUED只能主张“保留低排名状态以供重入可改善部分定位、但付存储与管理成本”；不能从视觉双向输入推断因果字节流。
