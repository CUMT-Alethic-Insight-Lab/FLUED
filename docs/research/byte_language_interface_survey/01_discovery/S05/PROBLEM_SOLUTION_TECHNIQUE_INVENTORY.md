# S05 granular problem → solution → technique inventory

2026-11-08. **54 non-synonymous records, covering all 35 works in WORKS.md (32 papers + 3 specifications).** This is material for classification and a long field survey, not proposal validation.

## Reading and schema contract

Each record supplies a specific prior problem, one-sentence solution, techniques actually employed by the researchers and their roles, units, learning signal, causal permissions, evidence/comparator/budget and remaining limits. The exact title, stable URL, version, era and family are resolved by the work ID in [WORKS.md](WORKS.md). `RC` locators below are **inherited from the actual old card**, not newly inspected original pages. `A` means abstract-only; a section is not invented where none was inspected. `P` names the selected original sections read. `N` is normative reference reading, not AI-model evidence.

Unit notation: `B` = UTF-8 byte unless explicitly alternate encoded; `CP` = Unicode code point; `C?` = paper says character but precise encoding/grapheme unit unverified; `SW` = subword; `G` = extended grapheme cluster; `H` = hidden state; `W` = word; `S` = generic discrete symbol; `Y` = task label. Each units field is **input / internal / output / supervision**. `CE` = cross-entropy; `AR` = autoregressive, predicting from previous outputs only; encoder–decoder models may additionally see the entire source. `OOD` = out-of-distribution; a new language, script, noise process or domain must be identified separately.

All technique entries are **explicit author use/report**, unless marked **analyst inference**. There are no claims that a deterministic Unicode grammar is an AI technique. Methodological recommendations after the tables are our synthesis, not additional paper results or counted records.

## 6. Classification-ready dimensions and unresolved comparison cells

These are synthesis dimensions, not additional inventory records:

1. **Actual interface:** raw UTF-8 bytes; Unicode code points; unresolved historical characters; morpheme-derived encoding; alternate scalar encoding then BPE; byte-fallback BPE. Never conflate these because a title says byte/token-free.
2. **Source of structure:** fixed Unicode grammar; fixed byte class; statistical BPE boundary; character convolution; morphology resource; learned script-dependent boundary; supervised byte-to-subword alignment; task loss alone.
3. **What robustness means:** legal UTF-8; intended scalar; exact byte string; task correctness under semantics-preserving noise; noise distribution transfer; random-initialization/byte-label variance; low-resource language adaptation. BMNMT ensembling and ByT5 typo robustness are different categories.
4. **Permissions:** full-source seq2seq; causal byte LM; offline boundary side information; query-first versus query-last; task-specific supervised compression; frozen-embedding probe. Probe recoverability and attention concentration are not causal generation success.
5. **Comparison contract:** equal positions, equal original text, equal original-text context, equal total parameters, equal nonembedding parameters, equal theoretical FLOPs, equal wall time and equal teacher/ensemble cost are separate axes. Record each available condition rather than choosing one favorable average.
6. **Metric object:** original-byte BPB; canonical-path probability versus marginal string probability; original/normalized exact match; CP or G edit distance; valid-character completion; whole-string copy; option likelihood; task chance floor. Synthetic random-byte entropy and multilingual natural text cannot share one difficulty interpretation.

### Exact offsets and floors: proposed extraction checklist, not attributed findings

For later reading/synthesis, retain `(original document ID, original UTF-8 byte range, code-point range, versioned grapheme range, model positions, normalized-text mapping)` wherever the source reports them. Mark unreported fields unknown. Preserve the same original text span before interface-specific cropping; give raw-byte context and content-bearing distance, not only model-position distance. Pair byte-leading/continuation errors with bytes remaining and complete-character exact match. Include same-length/script/frequency controls rather than comparing an unseen four-byte character to a seen three-byte one without stratification.

Report floor controls as actually appropriate: empirical majority/chance baseline for classification; random-candidate retrieval floor; shuffled/source-ablated control for evidence dependence; random-vector baseline for probe extraction; full-string rather than per-byte success for copy. A teacher-forced continuation is not generated exact copy. A low relative perturbation drop on a chance-level clean model is not robust useful language capability.

### Evidence still missing rather than negative

- Multilingual **grapheme-level** exact copy across normalization alternatives and long natural dependencies under a matched-byte/subword compute/text contract.
- Controlled Arabic/Indic/CJK/non-BMP numeracy and morphology evidence for modern causal byte versus token models; English digit/composition results cannot fill this cell.
- Byte-versus-token robustness with matched training text, original-text context and total deployment budget including ensembling/teachers; TokSuite's matched-text subset does not include its byte tokenizer.
- Real mixed-script/code-switched input for script-routed methods, legally complete output under streaming truncation, and benchmark annotations that preserve byte/CP/G offsets.
- Full-reading closure for new works; abstract claims remain candidates until Terra verifies method, controls, tables and relevant appendix.
