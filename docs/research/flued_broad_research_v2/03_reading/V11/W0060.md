## Problem, solution and objective

Older single-query, small-vocabulary synthetic recall hid failures observed in language modeling. **Solution:** measure repeated-bigram recall slices and introduce multi-query associative recall (MQAR), then use these probes to motivate input-dependent sequence mixing and attention hybrids. The work borrows associative-memory tasks, induction-like repeated n-grams, gated convolution, arithmetic circuits, one-way communication complexity and sparse attention. Training uses next-token prediction; synthetic examples supervise outputs for repeated key queries, not supporting-fact explanations.

App. E.1 splits an 8,192-token vocabulary into keys and values, randomly pairs them, chooses D pairs and places them at the beginning; a second occurrence of each key is placed at a power-law-selected later position and the paired value is predicted. Sequence positions, not independently retrieved documents, are units; multiple query positions and interaction distances are required in one causal forward pass. For the main sweeps N=64–512, widths 64–512, 2 layers, one attention head, 100,000 training/3,000 test examples, 64 epochs, four logarithmic learning rates 1e-4–1e-2, max test accuracy reported; architecture-specific optimizer/position choices remain (App. E–F). This bounded search is not a no-learning impossibility; use the existing W0088 retuning counterevidence at its own edition, not an unconditional architecture ban.

## Real data, permissions and negative controls

Pile AR-hit slice = last token of a previously occurring exact token bigram whose training frequency is at most 1,250; it is **6.4% of validation tokens**, the remaining 93.6% includes other cases (§3.1, App. C.1). Authors' average 82% is the capped fraction of the overall **log-loss gap**, weighted by slice prevalence, not 82% of all model errors nor a causal intervention proving every hit requires context. Rare bigrams are a proxy; semantic/fuzzy and unobserved recall are excluded. 70–360M runs consume 10B tokens; 1.4B uses 50B. Table 1, 360M attention vs Hyena: overall PPL 9.44 vs 10.07, hit PPL 1.98 vs 3.83.

Table 2, ~360M: pure BaseConv hit/overall PPL 5.98/11.01; random selection 6.17/12.94; programmatic selection 2.35/9.54; learned selection 2.61/9.59; 3 full-attention layers 1.95/8.59. Attention baseline 1.98/9.44. Full-attention improvement permits full source KV; programmatic policy uses raw token equality and previous occurrences, and its detection/access cost must be counted. Learned top-k selects positions across a batch/sequence with a sparse auxiliary loss; the report does **not** establish an equivalent online prefix-only top-k streaming implementation. Static random selection is a negative control, not matched mechanism proof. The model FLOP estimates are for N=2048, not complete deployment memory or measured serving latency. App. F sliding windows help within their reach and fail beyond it.

## Theory and decision

Theorem 4.4/H.37 is an **existence upper bound**, using structured theoretical projections, polylogarithmic depth and roughly `O~(N log c)` parameters, not a proof that all trained gated convolutions require width ≥ N. Theorem 4.5/H.38 assumes one-hot inputs and at most t interaction distances; its input-derived whole-sequence filter has unresolved causal cost/visibility (§4.3). H.6 reduces an indexing problem to one-way transfer of the recurrence memory, supporting an Ω(N)-bit lower bound for the specified exact AR regime; its matrix-element-to-bit step requires an explicit precision assumption. None implies fixed-bit unlimited exact arbitrary-history retrieval, nor negates stronger learned solutions under other recipes.

Directions **B.14–B.17, B.20–B.22** (also E.04/E.18): compare learned fixed-state query/write repair and selective updates without source revisit against local attention and source-access hybrid, matching bytes, data and tuning. Change the failure hypothesis if retuned closed-state systems solve varied loads/delays and new seeds on the same causal test, or if source-dependent hybrids lose after source residency and compute are counted. No byte-interface exoneration follows.
