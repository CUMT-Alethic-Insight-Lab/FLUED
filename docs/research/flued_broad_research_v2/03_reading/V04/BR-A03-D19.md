## Problem, one-sentence solution, borrowed role

**Problem:** autoregressive key/value caches cost memory even though selecting positions and transmitting the selected values play different roles. **Solution:** reduce per-head query/key feature dimension, retain value width, and optionally convert existing key matrices by truncated SVD with the remaining factor absorbed into ephemeral queries (§2). SVD is an approximate linear factorization and cosine/distance arguments are a theoretical motivation, not independent evidence that learned attention has retained every future query or its answer. Distinguish width of features, number of stored time positions, bit precision, and independent Q versus shared K/V: this paper primarily changes width, not the other axes.

## Learning, causal access and exactness

Causal next-token training writes per-token keys and full-width values; at decode a new query scores all visible past stored keys and receives their attention-weighted values. The full model still has residual and FFN paths; quality changes do not prove any individual returned value was used. From-scratch training is compared with full attention; post-training SVD uses pretrained Q/K, with optional QK-only fine-tuning on WikiText-103 for three epochs over 10M tokens, and an identically fine-tuned uncompressed control (§3.1, §3.4). GPT-2 QK adaptation ~21M of 124M parameters; Mistral GQA uses 32 Q/8 KV heads. Math recovery additionally uses 7,473 GSM8K training examples (~1.5M tokens), so this is task-domain supervised adaptation, not zero-shot recovery (§11).

For WK≈AB, replacing keys by xA and queries by qBᵀ preserves dot products of the **approximated** matrix AB exactly. The original v3/v4 §2.3 writes equality to original WK after a truncated SVD, despite its initial approximation sign; equality with original logits requires exact retained rank plus compatible position/rotation, bias and scale treatment. Orthogonal projection distance preservation under Johnson–Lindenstrauss requires an appropriate embedding, finite points and distortion; correct ranking requires margins and relevant query assumptions. Neither that lemma nor the toy 16-key task proves arbitrary semantic queries need O(log N) dimensions. Position-sensitive RoPE factorization cannot be assumed to commute with generic low-rank projections without the actual construction.

## Findings, costs, limits and version boundaries

v3 §3.1 reports GPT-2 K-only rank 384 +2.0% relative PPL and rank 192 raw +26–27.6% depending on passage; Q-only +181% at rank 192. After matched-control QK fine-tuning rank 192 gap +1.8%. Mistral rank 256 reported +2.0% gap (§3.4); GSM8K initially −13.7% relative; §11 Table 18 labels the gap −1.2% after in-domain fine-tuning, although its 53.7 control versus 52.0 compressed is a 1.7 percentage-point or approximately 3.2% relative difference. **Source conflict:** the same v3 p.8 Table 8 reports control 53.7 versus r256 51.2, i.e. −2.5 points, not the Table 18 value 52.0; no explanation is supplied. Table 7's 29.9 vs 25.8 gives a 4.1-point difference or ~13.7% relative, not 13.7 points. PDF tables were visually inspected; precise position/rank accounting and real deployment remain unverified. v3 §8.2 toy retrieval: 1 dimension/head 65.2%, 2 dimensions/head perfect, on eight random pairs, 16-token vocabulary; this is not a universal lower bound. WikiText-2 overfitting can make compression look free, whereas §8.4 reports +4.3% for quarter QK width at WikiText-103. For equal original K and V widths, 75% K-only saving is 37.5% total KV, not 75% total cache (§2.4). Speed needs measured kernel, context and batch; SVD conversion, fine-tuning, training and full serving costs remain separate.
