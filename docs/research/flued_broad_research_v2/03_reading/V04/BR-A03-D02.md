## Problem and solution

**Problem:** a neural Turing machine must learn to write and read useful facts; a recurrent controller can instead route around or misuse external memory. **Solution:** split each memory cell into a learned location/address vector and an episode-specific writable content vector, with soft or discrete addressing and training aids (§§2–4). Borrowed techniques: cosine content lookup, least-recently-used bias and policy-gradient credit assignment. Address vectors are global trainable model parameters fixed within inference, while contents reset to zero each episode and are erased/written at runtime (§2.1–2.3 Eq. 6). The memory is therefore a learned address system plus mutable state, not a growable KV cache or an external source query.

Read score compares a controller-generated key with the concatenation of address and current content; read value includes both, so fixed A can act as extra learned weights without accessing useful C. The authors report observing this shortcut, not a causal test that identifies it in another system (§4.3). A read/write-consistency penalty encourages read weights to overlap historical average write weights; this is distinct from next-input-prediction auxiliary loss and distinct from the continuous→discrete curriculum. All are training aids, not hard correctness guarantees. Soft attention backpropagates; discrete read/write sampling uses REINFORCE with input/global baselines, reward normalization and entropy, then argmax at test (§4.1–4.3). Curriculum chooses continuous or discrete heads with annealed probability; it is not direct address supervision.

## Read-order ambiguity and observed evidence

§2.2 orders read then erase/write and Eq. 6 defines C_t using C_(t−1), yet Eq. 3 describes r_t from M_t; key generation §3 also depends on h_t while §2.2 makes h_t depend on r_t. Supplied indexing is therefore not enough to assert whether each read accesses pre- or post-write state. Resolve implementation/pseudocode rather than silently relabeling. Multi-step heads can revisit within a timestep (§3.3), but exact intermediate versions likewise require missing material.

bAbI facts are encoded by a GRU to fact vectors; each task has its own model, 120 cells of 16-dimensional address/28-dimensional content, controller 180 units, 10% validation, Adam 0.003 GRU or .007 feedforward, batch 160 (§6.1). Table 1 mean error: LSTM 36.41%, MemN2N 4.24%, DMN+ 2.81%, three-step discrete D-NTM 21.79%, three-step soft 24.24%; advantage over its original NTM comparator does not overcome fixed-fact memory baselines. Feedforward discrete without curriculum 68.30% vs 37.79% with curriculum (§6.3), but feedforward was trained four times longer than recurrent: not an equal-opportunity GRU-vs-FF comparison. Newly completed §§6.4–9 add important negatives. Table 3 (p.15) continuous feedforward 12.81%, discrete 68.30%, curriculum 37.79%, and soft-trained/hard-tested 57.21% mean errors. Table 5 (p.17) pMNIST soft 93.4%, discrete input-baseline 92.3%, versus recurrent batch normalization 95.6%; no read/write-consistency penalty was used there. SNLI Table 6 (p.18): D-NTM + LayerNorm/dropout 82.3% vs NTM 81.8%, LSTM 81.7%, and word-by-word attention 83.5%; GloVe initialization is an external source. Visually checked Table 7 (p.19): discrete model passes copy but fails associative recall, while soft model and NTM pass both, under the author's in-training-length validation BCE<0.02 criterion. This is not proof of longer-than-training generalization.

C.01, C.05–C.08, C.17/C.19; E.01–E.03 and E.07: a low loss and learned address weights need not mean stored content is read. In the same trained model, scramble/zero the episode-specific content while preserving A and recurrent state; use matched nuisance interventions plus known-positive content substitution and original task quality.
