## Problem, intervention, learning

**Problem:** autoregressive KV cache size grows with number of layers as well as sequence length. **One-sentence solution:** consecutive layers reuse one earlier layer's K/V projections while retaining distinct layer-specific query projections (§2.2). Borrowed technique: grouped sharing, now across network depth rather than attention heads. It is an architecture trained from scratch using causal next-token loss, not post-hoc training-free conversion. SlimPajama GPT-NeoX BPE, length 2048, AdamW, linear 5% warmup/cosine decay, BF16 H100; 1B uses 30B training tokens, 3B uses 100B (§3.1–3.3).

Each token is written into the cache by the designated first-layer K/V producer; later layers read the same bank with their own contextual q. There is one writer per group and multiple independent readers, not multiple layers writing into one summary. Keys and values remain per-token full sequence; no learned compression of the token dimension or original-source fallback. CLA2 halves unique KV layers if divisible; storage savings do not guarantee bandwidth savings: the paper explicitly states shared cache is reread for each layer and core attention latency has no direct reduction (§2.3). Whole serving latency, reuse across pipeline stages, and energy remain measured-implementation questions (§4).

## Comparator frontier and negatives

At 1B, 16-bit bytes per token: H128 MQA 10,240, PPL 13.54; H128 MQA-CLA2 5,120, 13.60; H64 MQA also 5,120, 13.81 (Table 1). Sweeping LR changes all absolute results: H128 MQA at 1.5e-3 gives 12.39; H128 MQA-CLA2 at 2.25e-3 gives 12.43; H64 MQA at 2.25e-3 gives 12.74 (Table 3). The comparison is memory matched, not equal architecture or exact training FLOPs; authors state CLA slightly reduces parameters/FLOPs. CLA3/4 and nonuniform DenseFront/Back generally underperform CLA2 at comparable footprint; GQA+CLA2 is not uniformly superior (Table 1, §3.2.1).

At 3B, first LR-tuned comparison Table 5: H128 MQA 9.52 at 16,384 B/token, CLA2 9.34 at 8,192, H64 MQA 9.48 at 8,192. A second cluster/software/data order is a separately retrained comparison (Table 7); WikiText 12.94, 12.99 and 13.34 for H64 MQA, H64 CLA2, H32 MQA respectively. Downstream models have no consistent winner (Tables 4, 6, 8). Authors leave actual long-context serving efficiency to future work (§4): memory/PPL frontier is not observed end-to-end acceleration.

## Directions and rival explanations

C.14–C.16, C.06, F.10, R.16: layerwise writer independence differs from reader q independence and head sharing. Test same frozen layer bank and matched q/compute: own-KV, replayed shared KV, separate writer groups, and reader-only adaptation; then evaluate content-specific answer flips with all-state bytes and repeated cache traffic. Different learning rates, larger per-head width or regularization can explain some quality gains without any unique depth-memory mechanism; paper's LR sweep narrows but does not eliminate these alternatives.
