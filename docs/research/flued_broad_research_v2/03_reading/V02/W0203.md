**Problem / solution / borrowed role.** A key-side delta corrects key→value association but does not explicitly account for the distribution of similar value features over addresses. DDN adds a value-side state read and correction after the KDA key-side update (§3); this borrows two-sided associative memory and compact WY factorization to permit chunk training, not an external memory bank.

**Native update and units.** `S` is key×value per head. Decay `S̄=D S_prev`; `S_KDA=S̄+β k(v−S̄ᵀk)ᵀ`. Normalize current v to `v̂`, select features with token-derived sigmoid gate m, normalize `e=(m⊙v̂)/||m⊙v̂||`, define `τ=vᵀe`, then `S=S_KDA+γ(τk−S_KDA e)v̂ᵀ` (§3 eqs.5–10). Thus value-side correction reads the *post-key-update* state; Algorithm 1 computes both reads from pre-update S̄ but includes the cross-correction needed for equivalence. Native output reads updated `Sᵀq` (Algorithm 1 includes `dk^−1/2`; §2 writes unscaled, a presentation/parameterization distinction to check). Value-side read `S e` is explicitly not a guaranteed inverse semantic key. Current input drives q/k/v, β, m, γ and decay; next-token outer learning is AdamW, no direct stale-content labels. Query is causal; conv/residual and other layers remain possible paths.

**Cost and algorithm.** §3/Table1 reports one state read/write and leading 7dkdv versus 11dkdv FLOPs, arithmetic intensity estimates 1.75 vs 2.75 FLOP/byte under specified two-byte traffic; increased arithmetic intensity is not a speedup guarantee. Appendix B says value coupling prevents independent value-tile programs, with low-batch parallelism limitations; state/operands BF16 and accumulators FP32. Two rank-one updates, extra gating projections, caches and short conv must be counted. Appendix A WY lemma uses unit-lower-triangular inverse; reading its proof is not a proof verification.

**Results/negative evidence.** §5/Appendix C: 130M/340M/1B trained 5B/15B/50B FineWeb-Edu tokens at context 2048; total parameters matched approximately by changing model/MLP widths, main state entries matched by head-shape changes. Thus equal physical bytes for *all* state and equal compute are not shown. Against KDA/GDN-2/Mamba-3, DDN reports highest average NIAH each scale; six real-world retrieval tasks use ≤2048 inputs, greedy output and contains accuracy. At 1B, DDN average 31.20% trails GDN-2 31.80%; FDA 12.89 vs 17.42 (KDA 10.62), not a uniform win. At 340M ungated selector `e=v̂` retrieval average 23.48 exceeds gated 23.22, but gated downstream 43.44 exceeds ungated 42.16 (Table 6, p.9); these do not isolate extra computation. Table 3 (p.7) also shows 340M essay-number at 4096 DDN 14.4 versus KDA 40.6, despite higher overall DDN average. H200 Table 5 (p.8) reports 8192 prefill+decode 33.37s versus KDA 29.34s. The actual PDF correctly labels LM results Table 2 and NIAH Table 3.

**Rivals / minimal test.** Fix q/k/v and starting state; cross K/V overlap independently, ablate γ with equivalent projection/compute and a dummy second update, preserve state bytes/dtypes, compare retained *old* associations and new values, and vary latest/first-binding truth. Measure native answer dependence separately. Directions B.04–08, B.11–16, C.05, C.12–13, F.10–11. No conclusion that value-side reorganization causally explains natural-task gains.
