## Problem, technique, objectives, and units

A deterministic tokenizer returns one canonical token sequence, yet many vocabulary-valid token sequences concatenate to the same underlying string. The paper tests whether models become brittle when the *token IDs/boundaries* are changed but the decoded question string and correct answer remain fixed (§§2–4). This is not a test of arbitrary text corruption, semantic paraphrase, byte-level architecture, long-context retrieval or memory sufficiency. The vocabulary is fixed; perturbations operate on valid segmentations of characters/bytes, the models consume subword IDs, and evaluation uses multiple-choice answer likelihoods. For random tests, each question's candidate answers remain canonically tokenized, so this does not demonstrate unrestricted output-tokenization invariance (Appendix B.2).

- **STOCHASTOK**, inherited baseline: begin with canonical tokens and choose a current token uniformly, then choose a valid two-way vocabulary split. Algorithm 1 performs up to `min(Kmax, ceil(α·|v|))` attempts; if a selected token has no split, it stays unchanged. Thus α is a nominal expansion setting, not necessarily the realized number of splits (§2, Algorithm 1, p. 18). Appendix B.1 separately defines realized normalized split count as total splits divided by canonical token count.
- **STOCHASTOK-UNI**, new: sample a per-canonical-token split-count vector using a symmetric Dirichlet–multinomial model, then uniformly sample valid segmentations **conditional on each token's split count**, by subtree leaf counts. Its support is within each original canonical token; it is not uniform across the whole sequence or across all split counts. Its theoretical Polya-urn split-count correspondence presumes successful exchangeable splits; finite-vocabulary unsplittable tokens/skipped attempts and feasibility need care (§5.1, Algorithm 1, Appendix F).
- **UNIFORM-K**, new: use a multi-rooted multi-valued decision diagram to sample uniformly from valid segmentations of the **whole string** at specified token-edit distance k; it can cross canonical token boundaries. **UNIFORM** samples over the entire valid tokenization set without fixing k, typically producing many more pieces. Uniformity is relative to the declared support, not uniform raw text or model predictions (§5.1, Appendix F). BPE-dropout is a further comparison: its dropout probability is not directly comparable to α because actual split counts differ (§G.2.4, Table 10).
- Pretraining uses autoregressive next-token prediction with canonical or stochastic tokenization; for supervised fine-tuning the paper says the input can be perturbed while prediction targets stay canonical (Appendix G.1). In-context experiments keep weights frozen, perturb demonstration questions and query tokenizations while answer options are canonical. No future-token access or learned boundary mechanism is claimed.

## Experimental design and what is actually measured

The 50M Tiny-LLM has 8 layers, context 512 and a 50,257 GPT-style vocabulary; OpenWebText pretraining runs 30,000 steps × batch 480, stochastic αpre ∈ {0.1,0.5} vs canonical. Tiny-LLM supervised fine-tuning uses full weights for 3,000 steps × batch 480. Larger GPT2-xl, Llama-1b/8b, Qwen-0.6b and Gemma-1b use LoRA adapters, 1,500 fine-tuning steps, rank 8, scale 32 (Appendix A, Tables 4–7). Much of the study focuses on Language Game/CUTE spelling, letter and subword tasks; also ARC-E, COPA, CSQA, HellaSwag, PIQA and SocialIQA for few-shot/general tests (§4, Appendix C). Typical random-test protocol: 500 examples, 10 sampled query segmentations per example; answers scored by conditional probability (Appendix B.2). Some tables use one randomly sampled query each (B.4); do not silently mix these estimands.

The attacker searches alternative valid encodings of the same question, using correct-option and alternative-option model scores to greedily maximize wrong-versus-correct score margin. Neighborhoods use token-level edit distance with insertion cost 1 and deletion cost 0, ordinarily radius 2 per step; iterative greedy search is a **local adaptive attack**, not an exhaustive worst-case certificate. Appendix G.2.3 tests 10 greedy iterations, radius 2 or 4 and canonical vs random initial tokenization; adversarial access to token IDs and model scoring is a crucial condition (§2, Algorithm 2, p. 18). A deployed canonical tokenizer that does not accept external token IDs would have a different attack surface.

## Observations and counterexamples

- **Positive, random:** Table 2 p. 7, Llama-1b fine-tuned on Language Game: canonical training scores 94.0% on canonical queries and drops **29.8 percentage points** under uniform query tokenization. UNIFORM-K at αfine=1 scores 94.8% canonical and its uniform-query score is +2.8 percentage points relative to its own clean score; this is not a 29.8% relative decline or a universal downstream gain. Fig. 1 and §4 show other random-perturbation gains, but not automatically uniform-distribution robustness for STOCHASTOK (which samples with bias).
- **Positive, adversarial with residual failure:** Fig. 5 p. 8, same model/task, canonical vs greedy adversarial accuracy is 94.0%→6.1%; UNIFORM-K αfine=1 is 94.8%→69.6%. Stochastic fine-tuning improves the tested arm under this attacker, but 69.6% is not complete protection. Appendix Fig. 11 p. 27 gives a counterexample: canonically pretrained Tiny-LLM, Language Game, random-start attack yields 0.00–0.04 across listed stochastic α settings; clean UNIFORM fine-tuning accuracy 0.47 vs canonical 0.58. Stronger or alternative-start attacks matter.
- **Support vs uniformity:** Appendix G.2.3 Fig. 15 p. 30 holds two-way support fixed while varying its sampling, and separately expands to two-/three-way splits. For these Llama-1b tasks/attack settings the authors report larger support helps more under radius-4 or random-start search, while same-support uniformity has no significant improvement; this qualifies the main text's attribution to uniformity. It is a controlled comparison within these designs, not proof of a general causal law. BPE-dropout also improves tested robustness; Fig. 18 p. 33 and Table 10 stress α and dropout rate induce different actual split budgets, so methods are not directly exposure matched.
- **Clean/general negatives:** Table 8 p. 25: canonical OpenWebText validation token perplexity worsens from 29.77 to 53.06 for αpre=0.5, while noncanonical αeval=0.5 improves 474.72→30.28. These are **per-token** perplexities under different tokenizations, not a comparable byte-normalized likelihood. Table 9 canonical ARC-E accuracy declines 0.378→0.330 and COPA 0.660→0.610. TokSuite canonical average 0.3746→0.3623; e.g. contractions 0.5854→0.4146, although some subtests improve (§G.1.2). This explicitly limits any claim of cost-free clean quality.
- **Frozen-context comparison:** Table 3 p. 8, Llama-8b with ten demonstrations, Language Game canonical/uniform query: canonical demonstrations 83.9%/70.3%, STOCHASTOK αICL=1 87.7%/81.8%; on CSQA the clean result falls 68.3%→67.1%. Table 12 p. 37, five demonstrations, canonical/adversarial Language Game scores 83.8%/18.8% for canonical context vs 89.6%/51.0% for STOCHASTOK-UNI. Longer stochastic demonstrations can cost more context tokens; comparisons with parameter fine-tuning are not matched for training examples, tokens or compute (§4.3).

## Theory and interpretation limits

Theorem 6.2 and Appendix E pp. 19–20 propose a weight-norm/Lipschitz upper bound on adversarial output change for a **one-layer** transformer-like classifier, bounded embeddings and 1-Lipschitz activations, scaling with √k and model weight-norm factors. The proof explicitly argues via **k token substitutions in aligned one-hot columns**, although the threat set elsewhere permits variable-length tokenizations and insertion/deletion edits. Its extension to variable-length splits, positional shifts, real deep models and classification margins is not established in the presented argument. The bound itself does not compare canonical vs stochastic-trained weights or prove that stochastic training lowers risk; the paper's further smoothing explanation is an interpretation. Appendix B.5/Fig. 22 compare last-token pooled unit-normalized representation distances for 1,000 common English words × 50 tokenizations; body p. 8 instead says 10k tokens. This source-internal discrepancy and representational proximity do not establish functional causation or a Lipschitz certificate.

## Resource ledger and transfer

The paper claims no *additional inference cost* when the same deterministic tokenizer and model execution are used after stochastic training. This does **not** price altered inference inputs, longer stochastic contexts, generated token counts, training augmentation or adversarial search. §5.1 gives per-token segmentation-tree construction exponential in token byte/character length, O(2^(|x̃|−1)), then sampling linear in segments; whole-input MDD construction O(|x|·|V|), multi-rooted MDD O(|x|²·|V|). No actual GPU-hours, throughput, peak memory, energy, FLOPs, exact per-arm token/byte exposure or effective sequence-length distribution is disclosed in the paper's configuration tables. Matched steps and nominal split settings are not matched original-byte exposure, sequence lengths, FLOPs or wall-clock. α and fixed context interact; do not infer equal budget. Independent statistical seeds/uncertainty definitions are not consistently documented for the headline comparisons.

**Original research directions:** E.05–E.06: sampling/support might alter learned features, but intervention here tests tokenizer/training regime, not the FLUED gradient-starvation mechanism. F.17–F.18: tokenization shifts can require adaptation, with changed exposure/budget as competing explanation. I.01–I.03/I.22–I.27: distinguish same decoded text, input tokens, canonical target tokens and raw bytes; compare same underlying text, trained bytes, tokens, compute and effective context; evaluate multilingual/UTF-8 and downstream generation separately. The experiment does not prove that stochastic segmentation of a learned byte-boundary compressor improves long-range retention, causal deployed content use or retrieval; these remain target-project hypotheses.
