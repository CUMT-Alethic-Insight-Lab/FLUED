# W0112 — MemGPT: Towards LLMs as Operating Systems

**Status: FULL, exact assigned arXiv v2 (12 February 2024)**. [Original](https://arxiv.org/pdf/2310.08560v2); local `sources/W0112__2310.08560v2.pdf`, SHA-256 `9f674bcff69c86f11c813dcfad613d8841f5f8ed17979e3c4df06a91df7762e0`. **Problem → solution.** A finite prompt cannot hold a long conversation or document corpus. The proposed system borrows OS virtual-memory hierarchy, paging, interrupts and function calls: the model edits a limited working context and searches external storage, optionally chaining calls before answering. This is prompted agent control, not a newly trained memory objective or an end-to-end learned eviction policy.

**Permissions and lifecycle (§2, Fig. 3).** Static system instructions, function-writable fixed-size text working context, and FIFO message history are in the prompt; recall stores all incoming and generated messages and archival storage permits arbitrary text objects. At roughly 70% prompt capacity an alert invites saving; at overflow, a portion of FIFO is evicted and recursively summarized, but messages remain indefinitely in recall and must be searched to re-enter context. Heartbeat function calls allow multiple internal inference steps and paginated searches. Query/address units are search text and result pages, content is text, not fixed closed latent state; original sources, database, embeddings/index, summary and query calls all remain resources. No deletion, stale-index refresh, audit of backup copies, or physical erasure contract is established.

**Controls and findings (§3, Tables 2–3, Figs. 5–7; Appendix 6).** DMR session-six questions are LLM-generated from earlier multi-session chats and graded by LLM with ROUGE-L recall; GPT-4 + MemGPT scores 92.5% versus GPT-4 summary-only 32.1%, GPT-3.5 66.9% versus 38.7%. The comparator sees a lossy summary, not equal source and tool permissions. Wikipedia document QA uses 50 selected NaturalQuestions questions, shared embedding retriever but MemGPT can issue paginated archival searches; index uses precomputed embeddings, PostgreSQL/pgvector HNSW. Nested KV uses 140 UUID pairs, 30 ordering configurations and up to four nesting levels; GPT-4-based MemGPT outlasts direct prompting, but Turbo/3.5 variants decline as lookups are missed. Per-query call counts, failures, budget caps and full index/compute/storage costs are not provided in the reading. Appendix 6.1.4 and 6.1.6 explicitly tell the agent the answer is **always** in archival memory and nested lookup must continue until termination. This is privileged task-level answer-presence guidance, not a calibrated no-gold omission detector. Section 3.2 says it can stop paging early and retrieval ranking can miss evidence; quote denominators as unknown rather than zero failures.

**Evidence boundary and reversal.** Citation of relevant output plus the judge is not a source-swap causal test; no theoretical guarantee of unbounded accurate recall follows from unbounded external storage. Independent no-revisit alternatives include better closed recurrent write/retention and trained native readout; compare them with matched total resident bits and source-enabled flat retrieval, with cold/hot and full-call costs. Change the source-enabled hypothesis if same-source strong flat search at equal full budget matches the agent, if no-gold false-stop rates dominate, or if source mutations yield stale answers.
