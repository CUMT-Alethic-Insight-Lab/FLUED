**Problem → solution.** Training a memory encoder while accumulating cached activations makes old entries stale. LONGMEM borrows frozen-backbone side-tuning plus key–value retrieval: use the frozen language model to encode memory and train a residual SideNet as retriever/reader under autoregressive next-token likelihood. No task gold at inference; this is a source-enabled augmentation, not irreversible compression alone.

**Mechanics (§2–3).** Backbone 407M, 24 layers frozen; SideNet 151M, 12 layers initialized from alternate backbone layers and receives cross-network residual differences, using frozen output head. Per head a FIFO bank holds the most recent M K/V pairs, dropping oldest sequences and appending after segment processing; 65,536 tokens per GPU in training. Token query retrieves mean-pooled chunk keys via exact inner-product FAISS and flattens each selected chunk's original token K/V; 4-token chunks and 16 chunks (=64 token pairs) per token normally. A trained head-wise gate fuses local and retrieved content. App. B reports model/SideNet float16; it does not establish index precision or all cache/transport bytes. Frozen encoder avoids *training-time encoder drift under same weights*, not cross-model-version staleness, source revision invalidation or physical deletion. Memory can grow by design in other deployment claims; the evaluated FIFO is capped, plus retained source/index and host resources.
