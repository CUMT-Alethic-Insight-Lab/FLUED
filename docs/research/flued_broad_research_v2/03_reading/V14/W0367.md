# W0367 = BIW-0038 — Pseudo-Inverse Tying

**Reading: FULL**, scoped to the complete 15-page [arXiv 2602.04556v2](https://arxiv.org/pdf/2602.04556v2), 8 May 2026 preprint, not an asserted accepted venue. Original [PDF](sources/W0367.pdf), [extraction](sources/W0367.txt); SHA-256 `c788a12bd69fa8cecb547436b7b8b7327ceb4b0bb3a56432b44dfe5d0f8df1f7`. Read §§3–7 and Appendices A–C, including all reported comparisons and algorithm; no implementation or replication check.

**Problem → solution.** Transpose tying reduces token-interface parameters but does not make the input and output linear maps pseudoinverses. Construct a shared column-orthonormal vocabulary matrix and an invertible hidden-space metric so that the maps are pseudoinverses by construction. The borrowed machinery is polar/QR decomposition, Stiefel constraints, and Cholesky solves; the learning signal remains ordinary next-token cross-entropy, not a separate semantic alignment objective (§§3–4, App. C).

**Mechanism and assumptions.** With `Z` V×d, `ZᵀZ=I`, SPD `T=LLᵀ`, input `E=ZT⁻¹`, and output `W=T Zᵀ`, `WE=I_d`; `W=E⁺` under these full-column-rank assumptions. This is identity in hidden space, **not** recovery of every one-hot token: `EW` is only a rank-d vocabulary projection when V>d. The construction is not directly feasible as written for a typical 257-symbol byte vocabulary with d>257 because V×d cannot have d orthonormal columns. Small-vocabulary redesign and costs remain open. Positive Cholesky diagonal ensures mathematical invertibility, not a bounded condition number; FP32 triangular solves and optional diagonal clamp/ridge are numerical aids, not a universal stability guarantee. App. A.2 says `Z` is normally frozen after initialization; learned `L` and transformer parameters receive gradients. Trainable Z is optional with per-step retraction, but Algorithm 1's listed update names only Θ and L, so its trainable-Z gradient/update specification is incomplete. Checkpoint initialization uses polar factor; `T=I` is one stated option, and matching source scale is optional, so identical starting function is not established.

**Observed comparisons, not mechanism proof.** Table 1 reports Granite base training PPL 32.517→15.796 and Qwen3 base 33.976→28.111, with comparable but not identical wall time. Appendix B Table 4 reports all three random Llama-like PIT models *worse* than transpose tying (e.g. 0.3B PPL 50.166 vs 17.722); continued GPT-590M also worsens 33.892→41.027 despite improvements at 256M and 1.3B. App. B Table 6 adaptation is mixed, including GPT-590M HumanEval 19.2 vs 19.6. Training metrics are not held-out generalization or direct causality of geometric alignment. Authors compare FineWeb-Edu 10B-token subset, 1K context, within-comparison global batch and AdamW; exact full compute, checkpoint-equivalent initialization, and variability are not established. PIT adds d²-scale parameters/work and embedding solves, plus polar initialization and possible retractions; modest reported runtime on these large-vocabulary models cannot be extrapolated to bytes.

**Interface / alternatives.** Input and target are tokenizer units, not demonstrated bytes; separate decoder-input embedding tying is not tested. Vocabulary-coordinate consistency is neither memory content retention nor a native readout/use intervention. Relevant directions: I.13–I.17, E.02, C.10–C.12. Independent non-revisit alternatives are output-only normalization/temperature, untied or low-rank heads, and training schedule changes. A matched initialization, equal-compute factorial with trainable/frozen Z and a feasible byte-sized formulation, plus natural content-swaps, could change whether interface geometry is responsible.
