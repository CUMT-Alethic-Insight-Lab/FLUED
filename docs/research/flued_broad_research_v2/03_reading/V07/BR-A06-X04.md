# BR-A06-X04 — Functional Alignment Can Mislead: Examining Model Stitching

**Status: FULL — formal paper reading, not replication.** [ICML 2025 proceedings](https://proceedings.mlr.press/v267/smith25a.html), PMLR 267:55972–55998; [official PDF](https://raw.githubusercontent.com/mlresearch/v267/main/assets/smith25a/smith25a.pdf). **Problem / one-sentence solution.** Does high task performance after stitching prove two original representations encode the same information? The authors construct visually controlled shortcut, label-cluster and cross-task counterexamples where a trained stitch succeeds without the original models sharing input-level cues (§§1–5).

**Technique / supervised learning.** Model stitching is the measurement instrument: freeze sender prefix and receiver suffix, train only a randomly initialized 1×1 convolution with batch normalization before and after it, then compare held-out accuracy with the unstitched receiver (§2, p.3). For the main colour-MNIST model training, SGD uses four epochs, batch 128, learning rate 0.1, momentum .9 and weight decay 1e-4; ordinary stitching uses 10 epochs, batch 128, lr 1e-4 and weight decay 1e-2; noise stitching uses four epochs, batch 64 (§B.1, p.14). Cross-entropy-like task supervision is label-bearing; Appendix B.6 explicitly specifies BCE plus L1 for that separate regularization test. Real-data ResNet-50 stitching uses SGD 20 epochs, lr/weight decay 1e-4, batch 128, no stitch hyperparameter tuning and generally one run (§5, B.4). The paper does not establish equality of total pretraining, connector parameters, optimization compute or receiver task difficulty.

**What the synthetic input contains.** §4.2 and Appendix A, Algorithms 1–2 pp.13–14: draw one random activation-shaped prototype *per class*, then 6,000 train and 1,000 test samples per class add newly drawn Gaussian noise, clipping to [0,1]; the same class prototypes are shared between train and test. Thus class identity is deliberately built into the synthetic activations, labels train the connector, and there is no image-derived sender or test of fresh, unrelated random vectors. Separate test samples generalize within this same prototype/class distribution, not across unseen prototypes/classes. It is not a source-retrieval or causal sequence-memory experiment: input is image/activation, output is class label; no write/read/query visibility contract exists.

**Findings / negatives.** §4.1 uses correlated colour and digit labels so colour-only versus shape-oriented models succeed on the same evaluation distribution; §4.2 shifts stitch train/test to colour-only data when the receiver was trained on greyscale digits, which is explicitly an extended setting rather than original same-task stitching. Greyscale receiver 99.0±0.1% on its own MNIST task, stitched colour-only 100% on colour data. Table 1, p.6: noise→ImageNet top-1 at blocks 1/2/3/4/5/linear is 4.77/4.11/96.59/100/100/100 vs receiver 76.13. Stylized→ImageNet fails the stronger baseline (49.17 top-1 at linear vs 76.13), despite a much weaker alternate sender-task baseline; ImageNet→Stylized can succeed. Different domains and baselines are not a single controlled universal ranking. Appendix D.3 increasing noise radius .5→1 lowers MNIST accuracy 99.7→96.0 and colour-only 99.8→96.6; D.1 VGG early noise stitches vary by initialization (~40–80%). Appendix G reports both successes and failures for random untrained senders, depending on model, dataset, cut and seed; not every random sender works. Autoencoder cross-domain reconstructions (§6/B.3) use either supervised class pairing or batch-level embedding assignment and are qualitative, not evidence of same semantic content.

**Inference and next discrimination.** Relevant F.03–F.04/F.12/F.19, D.01–D.02. The established counterexample rejects stitch success ⇒ identical original input-level information, but does not negate practical connector utility or imply arbitrary fresh noise contains labels. Cross held-out prototypes/classes, permute class correspondence, and match connector capacity, optimization/data and receiver sham to distinguish a fitted class decoder from reusable semantic or computational correspondence.
