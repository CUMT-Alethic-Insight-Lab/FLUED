**Problem / one-sentence solution.** Bridge per-token discrete KV compression and recurrent aggregation while migrating a pretrained Transformer: use an intermediate soft circular codebook to align read/write projections, then progressively distill and fine-tune RAM-style slots (§§3–4).

**Writing, reading and visibility.** A causal token hidden state generates query/read and key/write distributions over product-code addresses, not semantic object IDs; values update per-address continuous slots with sparse top-K and a per-slot mass/forgetting term (§2.3, Eq.4). Current q reads selected slots, then a model predicts future tokens. GQA heads are repeated for migration. Fixed address slots are 4^5=1024 per head under the default, with top 32 active; actual resident bits include slot values, masses, projections and any implementation buffers (§5.1, B.2). This differs from quantized KV retaining every token. Real model uses unrestricted projection after initialization and native sparse read, not exactly the theoretical mass-weighted read.

**Theory and actual use.** §3.1–3.3 and A.1–A.5: restricted rank-at-most-two projections, shared circular codebook, fixed factors and small scaled query/key norms permit a local similarity approximation. The address overlap is exactly separable; the softmax-like mass-aware read equals recurrent aggregation in a cumulative-averaging limit (zero epsilon and no forgetting). Native read omits mass reweighting, and sparsity/forgetting change conditions. Appendix B.3 reports mass-aware better initial JS in six of nine models but generally worse final Wiki PPL, so nearer theory need not imply better trained deployment. Proof was read, not independently checked.

Sum 500.000M; AdamW no weight decay, BF16/FP32 masters, 16K tokens/step, best validation checkpoint restored after each stage. The 500M token ledger is not equal FLOPs, and teacher pretraining/search and training-time resident activations are additional costs.
