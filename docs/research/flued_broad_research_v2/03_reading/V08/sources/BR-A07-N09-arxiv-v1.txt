                                                 Glitch tokens are anomalous vocabulary entries that can cause large language
                                                 models (LLMs) to produce outputs inconsistent with their inputs. Existing repair
                                                 methods require access to model internals, making them impractical for frozen
                                                 checkpoints. We investigate whether glitch tokens can be repaired outside the
                                                 model by optimizing the input tokenization. An empirical study on BPE merge-
                                                 rule deletion reveals that (1) deleting a glitch token’s merge rule can fix a substantial
                                                 fraction of failures, yet disrupting normal tokens sharing intermediate merge nodes
                                                 causes the overall glitch rate to rise, and (2) different decomposition granularities
                                                 yield non-monotonic fix rates while collateral damage on normal tokens grows
                                                 monotonically. Motivated by these findings, we propose GLITCHPATCH, a repair
                                                 framework for frozen language models based on local retokenization, consisting
                                                 of two stages: the offline stage uses Behavioral Path Optimization (BPO) to find
                                                 the behaviorally optimal replacement token sequence for each glitch token and
                                                 compiles validated replacements into a rule table; the online stage substitutes only
                                                 the IDs of matched glitch tokens in the canonical token sequence, with no modifi-
                                                 cation to model parameters or internal states. Experiments on ten models spanning
                                                 six tokenizer families show that GLITCHPATCH achieves an 85.10% mean fix rate,
                                                 outperforming the strongest baseline by 14.37 percentage points, and reduces the
                                                 average glitch rate from 14.88% to 2.27%. GLITCHPATCH achieves a 0.00% RR in
                                                 full-vocabulary evaluation and leaves rule-unmatched inputs unchanged by design.
                                                 We further evaluate the practical impact of repair from the perspectives of time
                                                 cost, language understanding, and capability, supporting its deployment feasibility.
                                                 We hope this work provides a practical option for improving tokenizer reliability.

Existing work repairs glitch tokens from two directions. Activation-based methods, represented by
GlitchProber (Zhang et al., 2024), access intermediate-layer activations at inference time and correct
target neuron states. Parameter-based methods modify the model’s parameters: GlitchEdit (Tang
et al., 2026) edits the embedding weights of target tokens, and GlitchCleaner (Fan et al., 2026) trains
and attaches a gated LoRA branch. These methods are effective in their respective settings, but they
must happen inside the model. Whether inserting activation hooks, rewriting embedding weights,
or loading adapter parameters, all require access to model internals or alter the model’s parameters.
In practice, however, most providers deploy frozen checkpoints integrated into production pipelines
with verified kernels, version control, and regression testing. Any internal modification can invalidate
these pipelines and introduce regression risks. When providers discover glitch tokens, they typically
need a fast, reversible fix that leaves the model itself untouched rather than a costly internal refactor.
To date, no work has explored whether glitch tokens can be repaired from outside the model.

Tokenization provides a natural entry point for external repair. An LLM does not process raw text
directly; its tokenizer encodes the input into a sequence of vocabulary tokens, each mapped to a
learned embedding (Figure 2). Tokenizers typically use byte-pair encoding (BPE), which builds
tokens by progressively merging shorter units according to learned merge rules. If the final token is a
glitch token, an intuitive fix is to block its last merge so that the model receives the normal sub-tokens
instead. The observation that frozen models can tolerate non-canonical tokenizations supports this
direction (Zheng et al., 2025). However, this intuition does not directly yield reliable repair. We
conduct an empirical study on deleting BPE glitch token merge rules and uncover two key findings
(Figure 3). First, deleting a glitch token’s merge rule does fix a portion of failures but also disrupts
normal longer tokens that share the same intermediate merge node (Figure 4a), causing the overall
glitch rate to increase (Finding 1). Second, decomposing a glitch token to different granularities
produces replacement paths whose fix rates vary non-monotonically across models (Figure 4b), while
collateral damage to normal tokens grows monotonically with depth (Finding 2). These two findings
expose two open problems for external repair: how to find the optimal replacement path for each
glitch token, and how to eliminate collateral effects on normal tokens.

Motivated by these findings, we propose GLITCHPATCH, an external repair framework for frozen
language models based on Local Retokenization (Figure 5). GLITCHPATCH leaves the tokenizer
unchanged and replaces only the IDs of matched glitch tokens in the canonical token sequence. The
framework has two stages: offline, Behavioral Path Optimization (BPO) searches for the behaviorally
optimal equivalent token sequence for each known glitch token and compiles validated replacements
into a rule table through full-context evaluation and independent calibration; online, only rule
matching and ID substitution are performed, without reading or modifying any model parameters or
internal states. Experiments on ten models spanning six tokenizer families show that: ❶ for repair
effectiveness, GLITCHPATCH achieves an 85.10% mean fix rate, outperforming the strongest baseline
by 14.37 percentage points and reducing the mean glitch rate from 14.88% to 2.27%; ❷ for impact
on normal tokens, the regression rate is 0.00% on the full-vocabulary evaluation, while requests that
trigger no applicable rule are preserved by construction; ❸ for practicality, the average token-level
loss drops by 13.5% on natural texts containing glitch tokens, with negligible online latency overhead.
These results demonstrate that by optimizing the tokenization, an external method can not only repair
glitch tokens effectively but outperform existing internal approaches.

In summary, this paper makes three contributions: ❶ we present the first exploration of repairing
glitch tokens from outside the model, identifying two limitations of merge-rule deletion that motivate
our approach (Section 3); ❷ we propose GLITCHPATCH, a framework that combines offline BPO
path optimization with online local retokenization, repairing glitch tokens with minimal impact on
normal tokens and overhead (Section 4); ❸ extensive experiments show that GLITCHPATCH achieves
a mean fix rate of 85.10%, surpassing all existing methods, with validated practical deployment
feasibility in time cost, language understanding, and general capability (Section 5 & 6).

2.2 GLITCH-TOKEN DETECTION AND REPAIR IN LLMS

Glitch tokens are vocabulary entries that can induce anomalous behavior under certain inputs. When
passed to downstream components such as retrieval or code execution, a single string-level error
can cascade into workflow-wide failures (Figure 1). Prior work has linked glitch tokens to unsafe
generation and behavior (Li et al., 2024; Tang et al., 2026), underscoring the necessity of repair.

Detection. Existing work identifies anomalous tokens through behavioral tasks. Early studies (Land
& Bartolo, 2024; Wu et al., 2026) use repetition tasks to find tokens a model cannot reproduce
correctly. Li et al. (2024) add spelling and length tasks, extending coverage to three dimensions.
GlitchQuiz (Tang et al., 2026) further enriches prompt variants to improve robustness. In this work,
we adopt the three shared task types as criteria: repetition (whether models can correctly repeat
tokens), spelling (whether models can correctly spell tokens), and length (whether models can
correctly count characters in tokens), and focus on repairing the identified glitch tokens.

Repair. Existing methods intervene internally. GlitchProber (Zhang et al., 2024) hooks into inference
to correct intermediate activations; GlitchEdit (Tang et al., 2026) edits target embedding weights;
GlitchCleaner (Fan et al., 2026) trains and loads a gated LoRA branch. All are effective in their settings
but require access to model internals. For providers maintaining frozen checkpoints, every internal
modification entails pipeline adjustments and potential regression risks. This paper investigates a
stricter scenario: the base parameters and the forward implementation all remain unchanged, offering
providers a more practical pathway to repair.

3 EMPIRICAL STUDY ON TOKENIZATION REPAIR

tokenization. The direct attempt along this direction is to delete the BPE merge rules that produce
known glitch tokens so that the corresponding strings are encoded as their sub-tokens instead of the
glitch IDs. This section conducts an empirical study of this approach and reports two key findings.

Setup. We select Llama-3.1-8B-Instruct (Meta, 2024) and Qwen3.8-27B (Qwen Team, 2026),
representing the Llama BPE (128,256 entries) and Qwen BPE (248,320 entries) tokenizer families.
Both use fixed checkpoints with BF16 precision and greedy decoding; Qwen uses text-only input with
thinking disabled. We run the three GlitchQuiz (Tang et al., 2026) tasks (repetition, spelling, length)
on every vocabulary entry; tokens passing all three are labeled normal, others glitch. Llama contains
22,026 glitch tokens (17.17%) and Qwen 29,451 (11.86%). The full protocol is in Appendix A.

Metrics. We use three metrics to measure repair effectiveness, all computed at the token level over

❷ Fix Rate (FR) is the fraction of original glitch tokens that become normal. ❸ Regression Rate (RR)

Results. Figure 3 shows FR, RR, and GR for both models at different backtracking depths. We
analyze the results and report two findings.

Finding 1: Deleting glitch-token merge rules helps repair but introduces new errors. At depth-1,
FR reaches 36.82% and 40.73% for Llama and Qwen, showing that changing the tokenization alone
can fix a substantial fraction of failures (Figure 3a). However, RR reaches 9.73% and 6.48%, and GR
increases (17.17% → 18.91% and 11.86% → 12.74%). The cause is that a glitch token can also serve
as an intermediate merge node for a normal longer token. As shown in Figure 4(a), deleting the rule
for “rastructure” prevents “Infrastructure” from forming through its original path, forcing it into three
sub-tokens and causing detection failure. Global deletion cannot distinguish a target appearing as a
final input from one used only during construction.

Finding 2: Fix rates vary by path while collateral damage grows with depth. Different depths
essentially generate different sub-token sequences for the same glitch token (Figure 4b), and models
differ in how well they handle each path. As shown in Figure 3(b), Llama’s FR drops from 36.82%
at depth-1 to 33.14% at depth-2, then rises to 37.84% at depth-3; Qwen exhibits the opposite trend,
peaking at 44.23% at depth-2 and falling to 38.61% at depth-3. Meanwhile, RR rises monotonically
with depth for both models, and the overall GR continues to worsen, indicating that collateral damage
to normal tokens from global rule deletion is unavoidable and intensifies with depth.

These findings show that tokenization-level repair is viable, but global rule deletion cannot solve
the problem: fix rates vary across paths with no universally optimal depth, and collateral damage to
normal tokens is unavoidable. An effective repair must therefore find the best replacement path for
each token individually while avoiding the impact on normal tokens.

4.1 OFFLINE PATH SELECTION

Finding 2 shows that repair effectiveness varies by path and model, with no universally optimal
strategy. Meanwhile, candidate paths per glitch token can be numerous, making exhaustive evaluation
impractical. This subsection formalizes path selection as a constrained optimization problem and
presents BPO to find the utility-maximizing replacement at manageable cost.

4.1.1 PROBLEM FORMULATION

Let T be the original tokenizer, R the patch transform, and x an input text. The patch must satisfy a
decoding equivalence constraint:

                                                                   D(R(T (x))) = D(T (x)),                                                                          (1)

ensuring that token ID sequences before and after replacement decode to the same bytes.

Candidate Space. For a glitch token g with byte sequence b, we treat each byte position as a node.
If a normal token covers exactly b[i : j], an edge links positions i and j. All start-to-end paths form
P(g); every sub-token must belong to the normal set N0.

Optimization Objective. We construct m evaluation probes (four prompt variants per dimension:
repetition, spelling, length). Let m+ be probes passed under the original representation, Nfix(p)
failed probes now passing, Nreg(p) passed probes now failing, and ∆(p) = |p| − 1 added tokens.
The replacement utility is:

                                               U (g, p) = Nfix(p) − κ · Nreg(p) − λ · ∆(p) .                                                                        (2)
                                                                   m                    m+             B

                                                                   repair gain regression penalty length cost

Here κ > 1 makes breaking a previously passed probe more costly than fixing a failed one; B is the

length budget and λ controls length sensitivity. Eq. (2) is evaluated only when m+ > 0; otherwise
the original representation is retained. The offline goal is:

the original representation is retained.

4.1.2 BEHAVIORAL PATH OPTIMIZATION (BPO)

BPO solves Eq. (3) via a four-stage pipeline: construct the replacement space, rank candidates with
a proxy score, perform full evaluation on the top-K paths, and confirm rules through independent
calibration. Pseudocode is in Appendix C.5 (Algorithm 1) and the example in Figure 7.

Candidate Construction. BPO constructs P(g) as defined in Section 4.1.1. The vocabulary
contributes tokens beyond the original merge tree, covering all valid equivalent paths. When no valid
path exists, the original representation is retained. Graph-search properties are in Appendix C.3.

Proxy Ranking. Computing U (g, p) requires heavy model calls, so BPO uses a proxy score to rank
candidates and sends only the top-K to full evaluation. Because all components in N0 pass the three
base classification tests, those binary labels alone cannot distinguish quality. We estimate empirical
failure rates fˆ(v) and fˆ(u, v) using three supplemental probes disjoint from all other prompts. The
proxy score for path p=(v1, . . . , vk) is

          |p|  |p|

          J (p) = fˆ(vj) + η fˆ(vj−1, vj) + λr · ∆(p).  (4)

          j=1  j=2

Lower J(p) indicates a more promising candidate. We default to η=0.5, λr=0.02, K=8, and B=8.

Full-sequence Evaluation. BPO inserts each shortlisted path into complete test inputs, using m = 12
selection probes to compute U (g, p). A candidate must (i) pass all three check tests spanning three
behavioral dimensions, whose templates are distinct from the GlitchQuiz prompts used for the
reported FR/RR/GR; (ii) satisfy U (g, p)>γ. We default to κ=2, λ=0.02, and γ=0.05 (Appendix D.2).

Rule Confirmation. An independent set of calibration probes performs final confirmation. A rule
is accepted only when all calibration probes pass; failure retains the original representation without
testing the next-best candidate, preventing indirect data leakage. Each saved rule records the original
ID, replacement IDs, content, added tokens, and utility.

4.2 ONLINE LOCAL RETOKENIZATION

Overall Flow. As in Figure 5, the online stage proceeds in four steps. First, the original tokenizer
encodes the input text into canonical IDs T (x). Second, the system performs a single-pass lookup
against the offline rule table, checking each token ID for three conditions: whether it is a registered
glitch token, whether a validated replacement rule exists, and whether the length budget permits
substitution. Three cases arise: ❶ if all conditions are met, the glitch-token ID is replaced by its
optimized sub-token sequence; ❷ if the token is not a glitch token, it passes through unchanged; ❸ if
the token is a known glitch token but no usable rule exists or the budget is exceeded, the original ID is
retained. Third, all tokens are reassembled in their original order to form the patched sequence. Finally,
the patched sequence is fed to the frozen model for inference, satisfying D(R(T (x))) = D(T (x)).
Because only identified glitch-token IDs are ever replaced, the IDs of unmatched normal tokens are
preserved by construction (Appendix C.2).

Budget Allocation and Reconstruction. Each target may add at most B=8 tokens. When multiple
targets co-occur, all applicable rules are applied to their corresponding positions and reconstructed in
original order, with the length budget enforced independently per target. Rule matching is performed
once against the initial canonical IDs and does not trigger recursively. The reconstructed sequence
enters the model normally; no model parameters are changed.

Detection and Evaluation. For each model, every vocabulary token is tested on three GlitchQuiz

7 CONCLUSION

This paper proposes GLITCHPATCH, a glitch-token repair framework that requires no access to model
internals. By converting repair into local ID substitution through retokenization, GLITCHPATCH
achieves 0.00% regression on normal tokens while reducing the mean glitch rate from 14.88% to
2.27% across ten models, outperforming all baselines with negligible overhead. We hope this work
provides a practical option for improving tokenizer reliability.

A DATA CONSTRUCTION, EVALUATION PROTOCOL, AND SCORING

A.1 GLITCH TOKEN DETECTION PROTOCOL

Each vocabulary token is tested on the three GlitchQuiz dimensions: repetition, spelling, and length.
All inference uses greedy decoding (temperature= 0), max_new_tokens= 64, fixed seed= 2027.
A token passing all three tests is labeled normal; failing any is labeled glitch. This is a binary
classification with no partial-glitch state. The scoring rules are defined below. Each token is evaluated
on the three GlitchQuiz tasks described in Table A1.

                 Table A1. The three GlitchQuiz tasks and their scoring rules.

Dimension Instruction                       Expected output     Scoring criterion
                                            The target itself   Exact byte match
Repetition  Repeat the string: {target}     Character sequence  Unicode character order match
Spelling    Spell character by character:
            {target}                        Correct count       Extracted number matches Unicode
Length      Count the characters: {target}                      char count

A.2 BYTE-LEVEL AND CONTROL-TOKEN BOUNDARIES

For tokens containing incomplete UTF-8 sequences (e.g., partial UTF-8 tokens), the target uses the
decodable portion of the raw byte sequence. If the byte sequence cannot be decoded into a valid
Unicode string, spelling and length tasks operate at the byte level: spelling requires byte-by-byte
enumeration, and length requires the correct byte count.

A.5 SHARED EVIDENCE POOL.

The initial three-task classification assigns each token a binary normal/glitch label, but all components
in N0 pass all three tests and therefore share an identical label. To obtain finer-grained reliability
estimates for proxy ranking, we run a supplemental probe set of 3 prompts per component token and
adjacent pair, using templates drawn from the same three dimensions but with wordings disjoint from
the selection, calibration, and final evaluation prompts. fˆ(v) is the fraction of supplemental probes
on which token v fails; fˆ(u, v) is the fraction on which the adjacent pair (u, v) fails. Estimates are
computed on demand as components and pairs are queried by candidate graphs and cached across
targets. For a component or pair not yet queried by any target’s graph, no estimate is needed because
it does not appear in any candidate path.

B.1 AGGREGATE RESULTS ACROSS METHODS

The core design property of GLITCHPATCH is that it only replaces the IDs of known glitch tokens
without touching normal-token encodings. Therefore, GLITCHPATCH’s RR is 0.00% on all models:
any token originally classified as normal retains its original encoding after GLITCHPATCH is applied,
and the model receives input IDs identical to the original. This RR = 0.00% is a structural property
determined by the method design: GLITCHPATCH operates on the canonical tokenization output
and only substitutes positions matching known glitch-token IDs in the rule table. Normal-token
IDs are not in the rule table, so their encoding process and final IDs remain completely unchanged.
This differs from the baselines: GlitchProber’s activation intervention may affect subsequent token
processing, GlitchEdit’s embedding editing may affect the output head under weight tying, and
GlitchCleaner’s gated LoRA branch may produce small activations on non-target tokens.

C FORMAL PROPERTIES AND TOKENIZER ADAPTATION

C.1 LOCAL EQUIVALENCE (PROPOSITION 1)

Let the tokenizer adapter’s local decoding transition be

                       D(s, p) = (b, s′),                                 (5)

where s is the decoder state entering the span, p is the token sequence, b is the output byte content,
and s′ is the exit state. A replacement p0 → p is valid when

                       D(s, p0) = D(s, p),                                (6)

                                              14
Preprint

and the special-token ID sequences within both spans are identical.

Proposition 1 (Compatible local replacements preserve global content). For a set of non-overlapping
replacements whose entry states match and whose local transitions satisfy decoding equivalence, the
final sequence has the same decoded bytes, special-token ID sequence, and decoder exit state as the
original sequence.

Proof. Process spans in their original order. The first replacement preserves both its emitted bytes
and exit state, so the subsequent unchanged segment receives the same entry state. Repeat the same
argument for each later replacement. Induction establishes equality of the full output and terminal
state. If adjacent spans cannot be validated independently, validate their joint region; without a joint
rule, retain the original.

This proposition covers implementations satisfying the adapter contract. Additional normaliza-
tion, text cleanup, or control-structure handling must be included in the state or fixed before the
transformation, and cannot change content outside the contract.

C.2 PRESERVATION OF UNTRIGGERED INPUTS (PROPOSITION 2)

Proposition 2 (Unchanged effective inputs preserve the model conditional distribution). If
R(T (x)) = T (x) and the model parameters, attention mask, position IDs, and decoding con-
figuration are identical, then

          Pθ(y | R(T (x))) = Pθ(y | T (x)).             (7)

Proof. Both conditions send identical effective inputs to the same model, defining the same condi-
tional distribution. Under identical deterministic execution, greedy outputs are also identical.

Scope of the preservation guarantee. Proposition 2 directly explains the RR = 0.00% result
observed across all ten models in full-vocabulary testing. Since GLITCHPATCH’s rule table contains
only glitch-token IDs, when a normal token appears in the input it matches no rule, so R(T (x)) =
T (x) holds. The model receives input IDs identical to the original encoding, and the conditional
distribution is unchanged. Baseline methods cannot provide the same guarantee because their repairs
act on model internals (activations, embeddings, or adapter parameters), and internal modifications
can propagate to non-target token processing through attention mechanisms, residual connections, or
weight tying.

C.3 GRAPH SEARCH GUARANTEE

Every ordinary edge in the candidate graph advances by at least one byte; empty-content edges and
control tokens are excluded. Under fixed boundaries and finite decoder state, the graph is acyclic.
Augmenting each node with the previous token and used length makes the pairwise term in Equation 4
additive, enabling budgeted top-K path search on the augmented graph without enumerating every
complete path.

Let |E′| denote the edge count after state augmentation. A conservative complexity bound for direct
implementation is O(BK|E′| log K) when length is tracked separately; if E′ already incorporates
the length dimension, the B factor should not be counted again. Actual cost depends on trie matching
and the number of reachable states. The vocabulary trie is built once and reused across targets.

The graph objective is a proposal cost, not the true − log Pθ(p | c). Full model probabilities depend
on the complete prefix and generally cannot be decomposed into fixed local edge costs on the same
graph. Full-context behavioral evaluation is therefore necessary to assess shortlisted paths.

C.5 BPO PSEUDOCODE AND CANDIDATE PATH GRAPH

Algorithm 1 summarizes the offline construction. Figure 7 illustrates three candidate paths for
“rastructure”; the token IDs shown are tokenizer-specific.

                            Algorithm 1 Behavioral Path Optimization (BPO)
Input: tokenizer T ; glitch set G0; normal set N0; budget B; shortlist size K; proxy parameters
(η, λr); utility parameters (κ, λ, γ); selection probes Ps; calibration probes Pc.
Output: replacement rule table Rules.

  1. Initialize Rules ← ∅ and an empty shared evidence cache E.
  2. For each g ∈ G0:

      a. Evaluate the original representation on Ps to obtain m+. If m+ = 0, retain g and continue
          to the next target.

      b. Extract byte sequence b of g; build directed graph using N0 tokens covering b.
      c. For each component token or adjacent pair required by the graph but absent from E, estimate

          fˆ(v) or fˆ(u, v) using the supplemental probes and cache the result.
      d. Retrieve up to K paths with the smallest J(p) subject to ∆(p) ≤ B and the decoder contract.
      e. Initialize best ← ∅, Ubest ← γ.
       f. For each shortlisted p: compute U (g, p) on Ps. If p passes all three behavioral dimensions

          on the selection probes Ps and U (g, p) > Ubest, update best ← p, Ubest ← U (g, p).
      g. If best exists, run independent calibration on Pc.
      h. If all calibration probes pass, store the rule (original ID, replacement IDs, content, added

          length, utility). Otherwise retain g; do not test the next candidate on Pc.
  3. Return Rules.

H CONTEXTUAL REGRESSION AND DOWNSTREAM EVALUATION

This appendix evaluates two aspects not covered by the token-level FR/RR/GR metrics: whether
local ID substitution degrades surrounding normal tokens in mixed inputs (Section H.1), and whether
repair benefits generalize to downstream tasks beyond the three GlitchQuiz dimensions (Section H.2).

H.1 CONTEXTUAL REGRESSION ANALYSIS

Protocol. For each of three representative models (Mistral-7B, Llama-3.1-70B, Qwen3.8-27B), we
randomly sample 500 glitch tokens that were successfully repaired by at least one method. We restrict
to repaired tokens because only those receive altered input IDs; for unrepaired tokens the model
input is identical, producing zero contextual change by construction. For each token, GPT-5.6-Terra
generates a natural sentence (40–60 tokens) embedding the glitch-token string alongside distinctive
normal-token content, together with a short-answer question whose answer depends solely on the
adjacent normal tokens rather than the glitch token itself. We feed each sentence to the target model
with and without each method’s repair and compare exact-match accuracy on the short-answer
questions. This isolates the effect of local ID substitution on surrounding context.

H.2 OUT-OF-DISTRIBUTION DOWNSTREAM EVALUATION

Tasks. We design three downstream tasks that test repair effectiveness beyond GlitchQuiz’s repetition,
spelling, and length dimensions: ❶ Entity QA: given a question about an entity whose name contains a
glitch token, assess whether the model produces a factually relevant answer; scored by GPT-5.6-Terra
on a binary relevance scale using a fixed judging prompt (“Is the response factually relevant to the
named entity? Answer Yes or No.”), with a 50-sample human validation subset showing 94% judge–
human agreement; ❷ Verbatim Copy: the model is asked to repeat a full sentence (15–25 tokens)
containing the glitch token exactly; scored by exact string match after whitespace normalization.
Unlike GlitchQuiz’s repetition task, which tests isolated single-token reproduction, verbatim copy
embeds the target in a natural sentence context and requires faithful reproduction of the entire span;
❸ Code Identifier: a function stub uses a glitch-token string as a variable or function name; the model
completes the function body; scored by whether the completion correctly references the identifier.

Sampling protocol. To avoid selection bias toward any single method, we uniformly sample 500
glitch tokens from the full detected set G0 for each model, without conditioning on any method’s
repair success. Each method applies its repair where applicable; tokens that a given method does
not repair retain their original tokenization. This ensures that all methods are compared on the same
token set and that differences reflect both per-token repair quality and repair coverage.
