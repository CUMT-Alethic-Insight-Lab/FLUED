## Original problem and method

Why does one language's training data convey so little usable factual knowledge in another? **One-sentence solution:** expose a controlled synthetic-fact set to bilingual training and map semantically corresponding words into shared token space, using clone-language and shuffled controls to distinguish token alignment from shared inventory. Borrowed techniques: autoregressive language-model pretraining, byte-pair encoding (BPE), pretrained-model-generated translations/paraphrases, linear regression and semantic embedding probes. This is a multilingual interface/knowledge-acquisition paper, not a recurrent-memory architecture.

360M SmolLM2-style and 7B Llama-style models are trained from scratch on next-token loss, AdamW, warmup/cosine: 7.2B and 140B tokens respectively (A.1–A.4). They use 50/50 token language budgets; translation-derived Arabic and English documents are split disjointly, with native Russian as another control (§3). Each condition is one pretrained run, not a matched seed distribution (D.3).

FKD comprises 2,048 invented entity–attribute facts. For each fact, varied model-generated documents are injected at target exposure levels 0/20/100/1000 per language; five separately generated four-way MCQs evaluate the held-out formulations (§2, §3.2, B). Thus state is persistent learned model weights; address is a prompted entity/text token sequence, output is MCQ option likelihood, not an external writable store or online learned retrieval. Foreign knowledge is in pretraining weights before the evaluation prompt, not supplied as test context. Attribution to native deployed long-context use is unsupported.

Cloned English (§5.1–5.4) applies the *same* base token segmentation to one language's text, maps the second copy by token ID +V, and doubles vocabulary. Ordinary data may be identical across copies, except fact-injection schedules. Baseline CLeq −2.6% at 360M and −1.5% at 7B; same ordinary corpus −0.1%. Shared pair initialization without enforced tying gives 78.6% and same-corpus initialization 84.6%; learned pairwise geometry is therefore not automatically maintained. Soft mapping shares a chosen fraction of corresponding embedding dimensions; 20% gives 8.6%, 50% 82.7%; A/H explicitly distinguish 360M tied input/output matrix and 7B separate output head. H compares aligned embeddings with linear maps fitted on 80% of eligible tokens and evaluated on 20%; a decodable map is not the model's own native cross-lingual use.

## Supervision, results, costs and caveats

- Word-wise translation (WWT) is **additional semantic cross-lingual supervision**, not an unsupervised tokenizer-only change: Qwen2.5-32B-Instruct translates 11M Arabic word entries; conflicts require indices and out-of-dictionary fallback is reversible transliteration (G.1–G.4). It is context-free and preserves word order but does not remove the teacher/dictionary construction cost. The fictional fact templates, translations, documents and MCQs also use generative models (B.1–B.3). Inference requires a language selection for full WWT; soft mapping has distinct IDs but its code-switched generation is not directly evaluated (F.3).
- **CLeq is a slope ratio**, 100 × foreign exposure coefficient / native exposure coefficient for each direction, averaged across directions (§2.2); it is neither factual accuracy nor fraction of all knowledge retained. At 360M English–Arabic: 0.9%→12.6%, ≈14× relative to the baseline, i.e. 11.7 percentage points; English–Russian 1.9%→23.3%, and 7B Arabic 5.9%→12.5% (§§4, 6). The abstract's “up to 12.6%” is narrower than the 23.3% Russian number in §6.2/K.1; preserve both contexts rather than silently reconciling them.
- Controls: shuffled Arabic dictionary 3.0%, transliteration −0.3%, permuted shared clone IDs −2.6%; semantically meaningful mapping matters in these tests (6.4/K). Frequent-token sharing can work with few types: 2% most frequent gives 59.9% CLeq in clones, yet anchored Arabic gives 1.6% (I). Similar source/target geometry alone does not prove usable correspondence. Negative numerical estimates near zero are authors' noise-floor interpretation, not proven negative transfer.
- Nonlinear acquisition is fitted by linear OLS; alternative nonlinear fit has better residual fit but a harder-to-identify parameter (D.1–D.2). Paired bootstrap over the same entities reports WWT-baseline +11.7 pp [7.5,16.1], **evaluation/entity uncertainty only**, not seed uncertainty (D.3); target vs realized injection is checked in only two runs (D.4). Common-name controls show higher baseline and much noisier ratios (C). English perplexity improves 19.53→18.74; native-byte Arabic BPB worsens 0.7129→0.7160 at 360M (J). WWT Arabic increases token count 29.9%, Russian 22.6%, and fixed token budgets expose ≈23% fewer Arabic documents (G.3). G.2's caption says larger Russian fertility; its actual displayed relative increases instead favor Arabic, while Russian has the larger absolute token increase (PDF p.31). Neither uniform information exposure nor equal wall time is established.

## What this changes / unresolved tests

Relevant original coordinates **I.01–I.03, I.22–I.25, I.28, E.04–E.06, F.17–F.18**. Controlled clones show lexical-code separation can suffice to impede measured synthetic-fact transfer; they do not prove it is the only cause for all natural languages or that shared bytes solve cross-script semantics (§8). Rival accounts: semantic supervision, token-frequency/segmentation, changed parameter budget, training-data coverage, evaluation denominator or reader mismatch. Prospective minimal discrimination: same raw parallel content/exposure and total compute, vary ID matching vs shared inventory vs semantic dictionary, measure both directional raw accuracy and CLeq with multiple seeds and legal post-training readout; count dictionary teacher and all generation tokens. No target-host diagnosis follows.

**PDF cross-check:** Table 2 p.7 directly shows all three baseline/mapped comparisons, including Russian 23.3%. Table G.2 p.31 confirms 709→921 (+29.9%) Arabic versus 1,190→1,459 (+22.6%) Russian; its caption's “more so for Russian” conflicts with the displayed *percentage* changes, though Russian has the larger absolute 269-token versus 212-token increase. Figures B.1/C.1 pp.23–24 directly show saturation and the high common-name baseline; H.1 p.33 compares calibrated geometry, not deployed use.
