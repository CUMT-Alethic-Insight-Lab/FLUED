# BR-A08-V23 — LinQuant: Functional Invariances for Low-Precision Linear Recurrences

**Reading:** FULL public [arXiv 2610.39418v1](https://arxiv.org/pdf/2610.39418v1), 2026-10-29, main body and Apps. A–F including exact-arithmetic proofs and production controls; [PDF](sources/2610.39418v1.pdf), [text](sources/2610.39418v1.txt). Its anonymous title-associated [ICLR 2027 submission](https://openreview.net/forum?id=6egpMpGwZE) is a submission at the audited snapshot, not accepted, and content equivalence is unknown. No code or kernel executed.

**Problem → solution.** Quantizing chunkwise linear recurrence operands can introduce errors although mathematically equivalent recurrence realizations produce the same real-valued output. Use function-preserving basis changes and redistribution of decay/write factors to reshape quantizer inputs, then fuse feasible transformations into low-precision prefill (§§1–3). Borrowed orthogonal rotations, SmoothQuant-style reciprocal scaling and chunkwise delta-rule solves; this is post-training calibration, not a new language-model objective.

**Seven transformations and constraints.** (1) Q/K orthogonal rotation; (2) reciprocal diagonal Q/K scaling; (3) value rotation; (4) value scaling; (5) scalar decay absorption; (6) diagonal decay's scalar-part absorption; (7) write-factor absorption. App. C proves identities in exact arithmetic with positive gates and consistently transformed initial state. A global key rotation commutes with scalar but generally not channelwise decay; diagonal-decay local score rotations remain possible. Reciprocal key scaling does not preserve general delta correction. Value transforms require inversion before noncommuting output normalization; convolution/nonlinearity means apply rotations online after them. Diagonal decay cannot generally be entirely shifted to values. For delta writes, gate redistribution also changes the Gram triangular system; simple operand movement alone is insufficient.

**Evidence and budgets.** Controlled 340M/15B and 1.3B/100B SlimPajama zoo, 2048-token pretraining; static calibration on eight WikiText-2 windows and held-out transform selection (App. B). INT6 is simulated in INT8 kernels to enlarge error; controlled state carry is FP32 with an INT8 read copy, not low-bit carry. Table 9 explicitly shows recurrently requantized carry adds further error. Gram/WY solve remains FP32. Production Mamba-2/Nemotron-H uses W4A8 projections and INT8 fixed-point recurrence prefill; Mamba-2 1.3B Wiki PPL 10.928 SSDi8, 10.860 rotation, 10.849 rotation+rescaling, versus FP16 10.420 (Table 2). Measured A5000 T=2048 end-to-end prefill shows no measurable overhead for fused rotation; separate value rotation can be costly. At 2.7B rotation+rescaling 9.383 is slightly worse than rotation alone 9.379; task accuracy does not always follow PPL (Table 17). Static decay-placement comparisons differ in mean-correction settings (App. F), so do not attribute all differences to decay alone.

**Content/causal limit.** Prefill token granularity and matrix state axes are not semantic content units. Exact equivalence precedes quantization, not a guarantee of equal low-precision behavior, long-duration low-bit memory retention, or native fact recall. Production timing does not establish autoregressive decode latency or all-host generality.

**Directions:** B.11–B.12/C.12/F.10/R.16. Independently test per-channel quantization, gated-write redesign, reader-side adaptation, or more precision/memory instead of extra granularity. Reverse the hypothesis if same-precision repeated state-carry, long-delay and matched-latency accuracy controls lose the prefill quality benefit, or if host gates invalidate the required commutation.
