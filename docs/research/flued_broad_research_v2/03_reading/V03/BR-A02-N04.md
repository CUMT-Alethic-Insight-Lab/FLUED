# BR-A02-N04 — SPARE: Fast Linear Attention Decoding with Compact Recurrent States

**Question and technique.** Dense fixed recurrent matrices are bandwidth-heavy; project each head's keys and queries onto a fixed calibration-derived PCA subspace, allocate rank heterogeneously by state spectra, and compensate for projected-key norm loss (§3). It is post-training calibration/compression, without recovery fine-tuning or new task labels, not a new memory training objective.

**Native contract.** Each token's k,v updates a compact FP32 coefficient matrix, q reads the updated state and native model continues generating; no original-source return in the pure recurrent core, but preserved short-convolution caches give an additional local path. It is not a probe-bank win: four-choice model answers are scored. Calibration keys follow the original convolution and normalization; PCA bases are fixed across later sequences and shared across requests. Spectral ranking uses states; key PCA need not coincide with state singular directions (§3.2).

**Exactness and budget.** Theorem 1/App.A.1 requires fixed orthonormal basis, compatible initial state, every unit key inside its span, identical input/gates, and suitable epsilon/cap; then induction shows equal state/readout. This is a conditional real-arithmetic statement, not proof calibration contains OOD keys or finite-precision learned-use equivalence. Eq.9 compensation restores write strength only while floor and cap are inactive; it cannot recover a projected-away direction. The 1.3B pure GDN has 24×8 heads, 256×256 FP32 states; 48 MiB dense vs 6/12 MiB compact **per request**. Shared bases, short-convolution state, temporary prefill workspace, graph allocations and model weights are excluded from state budget (App.B.1/B.5). Fixed-batch RTX A6000, prefill 128 and decode 64 steps; H32 at batch512 reports 2.55× full-model speed, 7.49× recurrent DRAM reduction, 3.31× peak GPU memory reduction (§4/Figs.2–3), not a continuous-batching result.

**Positive and negatives.** Table 1 p.6: Dense retrieval 70.51%, H32 56.84%, H64 60.35%; matched 12 MiB DRRQR-K64 33.20%. H64 TriviaQA 48.40 is below K64's 50.12; both compressed models degrade against dense. Table 2: at 6 MiB uniform rank has NLL 2.798 versus heterogeneous 2.817, despite retrieval 33.59 versus 56.84; at 9 MiB 2.658 vs 2.680. Fig.4: same-basis/rank-allocation comparisons give compensation gains 7.62/11.13 percentage points; basis comparison disables key-side compensation, so it does not prove independent optimality under all updates. Four-choice test 512 prompts, half at retrieval depth64, half128; exact randomization and shifted semantic-query performance not documented.

**Discriminator.** Hold calibrated basis/rank/bytes fixed and ablate compensation; independently vary rare/OOD key directions and answer identity at fixed state/workspace and assess native final-answer content dependence; account for PCA calibration and full serving memory. Prior directions **B.11–B.13, B.17, C.09–C.11, C.14–C.15, D.01–D.04, R.16**. This supports an efficiency–quality trade-off, not a general state-capacity theorem.
