**Problem and solution.** Are poor recall results architectural incapacity or fragile optimization? The authors retune learning rates, widths, depths and components on synthetic associative recall and copying. Borrowed methods: AdamW and supervised synthetic in-context binding; recurrent and attention mixers are comparators, not a proposed new architecture.

**Task, native flow, training.** Tokens from a shared 8,192 vocabulary serve as variable key/value roles; sequences give fresh bindings before subsequent queries, while copying reproduces an initial token string after a delimiter (§2, App.A.2). Recurrent models write prefix information into learned fixed states and natively predict values; attention instead reads accessible earlier tokens. These are not source-revisit-equivalent memory budgets. There is no explicit future-query signal during writing, no separate teacher or oracle reader. No content intervention establishes semantic use.

**Actual budget and results.** App.A.2 pp.16–18: 100,000 train/3,000 test examples per length; (length, pairs)=(64,4),(128,8),(256,16),(512,64), same-length train/test; widths 64–2048, one/two mixer-plus-MLP layers; AdamW, 50 epochs, weight decay 0.1, 10% warmup, batches 512/256/128, seeds 42/123/777. Per-configuration best LR selected; over 3,000 runs and ~20,000 GPU-hours (§1). The complete LR grid is not enumerated in the paper; plotted Fig.1 spans 1e-5–0.3 for the displayed MQAR runs.
