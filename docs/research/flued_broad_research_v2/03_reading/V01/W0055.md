**Problem / solution / technique.** Document text makes retrieval-augmented generation expensive. Treat an existing dense document embedding as another modality and learn a two-layer projection into one language-model input embedding per retrieved document, borrowing frozen-encoder multimodal bridging and teacher distillation (§3). Query selects a document, but document embedding is precomputed independently of that later query; the query itself is passed as ordinary text to the reader. One input token is a high-dimensional real vector, not one bit or a fixed-size whole-corpus state; the source datastore and index persist.

**Learning and visibility.** §3.2 trains the projector to generate original document tokens from its embedding using a paraphrase instruction and causal preceding gold tokens—despite the name, the target is original D, not independently paraphrased labels. §3.3 uses ~1M instruction examples comprising context/question/answer from reading comprehension, QA and summarization; answer NLL plus KL from the same frozen LLM given full document as teacher. Only projector trains, frozen retriever and Mistral-7B/Mixtral-8×7B reader; each host has a bridge, not evidence one unchanged bridge transfers between hosts. Teacher sees full text and question, student the projected vector and question; teacher forward/training data are nonfree. Default top-1, ~37M Wikipedia passages, mean ~180 tokens. §4.2 calls SFR the default retrieval model; Appendix D says actual top-1 is pre-retrieved with ColBERT-v2 then re-encoded using SFR—preserve both and do not silently equate retrieval and payload encoders.

**Observations and controls.** §4.3/Table 1: no-retrieval, full-text retrieval, TF-IDF one-token and LLMLingua baselines share selected documents. **Cost/interpretation and directions.** §5.2 profiles Mistral/A100, batch averages over four datasets, reporting 1.64× CUDA-time efficiency and 3.53× GFLOP reduction per generated token, not whole-lifecycle training, embedding/index build, storage and retrieval cost. Projection adds no *additional* stored vector only if reusing an already-required compatible document embedding; ColBERT-to-SFR re-encoding is explicit. Directions A.01–A.02/A.06/A.16/A.19, D.02–D.05 and F.01/F.05.
