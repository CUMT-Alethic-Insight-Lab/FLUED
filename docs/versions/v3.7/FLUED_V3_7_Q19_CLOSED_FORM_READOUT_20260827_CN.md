# FLUED v3.7 — Q19 闭式三段臂（容量墙重审，零训练）预注册任务书（冻结）

> 冻结时刻：2026-08-27。来源：fable5 评审 Q7 节（其内编号 Q7；本仓队列 Q7 已被"300M L0 codec"占用，故注册为 **Q19**）+ 用户裁定"Q19 先行，Q18 定稿等 Q19 落叉"。
> 上游：E73（ridge 解混 oracle 态 cos≈1）、E88/E97（zero_V=0.3185 旁路判词）、E109（Q17 点火失败+§6 勘误）、Q16（init 本底纪律）。

## §0 定位（一句话）

登记册里已有三段闭式件；拼起来就是一条零训练读出管线。**"墙"在数学上若是表示容量，闭式解就不可能存在**——本臂把"容量墙终审"从"两个不锚同一量的锚"变成有分段损耗台账的真判词，且可能产出赛季首个阳性格（审稿人索要的"让它工作一次"）。

## §1 管线（全闭式，零训练）

```
状态行 S_i ──(段1: ridge 解混, E73 同款, oracle 态 cos≈1 已有)──▶ v̂（写值估计）
          ──(段2: ridge 回归 v̂→m̂, 新拟合, 缓存张量闭式几分钟)──▶ m̂（memory 行估计）
          ──(段3: 冻结生产 decoder 的 direct 口——decoder_in_mem(m̂)+pos→decoder, 已知消费 memory 行 ~0.6–0.7)──▶ 字节
```

**对象与态**：基座 = Q15 正臂 checkpoint（d 格，冻结前端+写头出 gates）；四种输入列：
- **oracle 态**（E73 同款 Σ k_j v_jᵀ，α 范数匹配沿用 Q17 §1 条件 2 公式）；
- **自然态**（KDA 递推原样）；
- **置乱态地板列**（Q17 程序缺口 (a) 补齐：状态行打乱——地板对照，规则 6 纪律）；
- **明文行正对照列**（程序缺口 (b) 补齐：memory 行直喂段 3——"同解码面读易输入能不能过线"，与状态无关的 decoder 能力上界参照）。

**段 2 的训练/测试纪律**：ridge 在训练窗拟合、held-out 窗评测（2-fold 或独立窗 split），majority 基线与 real−garbage 同族口径；全部拟合是闭式解，无梯度、无训练动力学。

**考场**：eval 窗（seed 1042）codec direct 形态逐槽 byte_acc——与 0.3185（E87/E88 旁路参照）/0.62（E73 写值探针段首槽）/0.48（A6 全槽均值修正值，fable5 核）同一读数家族。

## §2 判读三叉（预注册阈值）

| 结局 | 判词 |
|---|---|
| oracle 态端到端 ≥0.4 | **表示容量墙死刑**——零训练闭式解越过 0.3185；Q17 判词降级为"可学习性墙"，修复路径具体化（闭式解蒸馏/温启动读出链）；"让它工作一次"到手，ICLR 叙事（完整失败拓扑+唯一工作点+修复路径）复活 |
| oracle 态也只到 ~0.1 档 | **墙硬化**——逐段损耗台账精确指认死在哪一段（v̂→m̂ 不可逆？decoder 对 m̂ 分布外？），比"2K 步训不出来"硬一个量级 |
| oracle 高、自然态低 | **墙移址**：delta-rule 叠加对 post-state 线性可分性的破坏——K 侧几何线带定量目标复活；自然态该数字 = 全赛季缺失的"读出链实际消费张量上的线性信息天花板"测量 |

**辅助判读**：置乱态地板列必须贴先验（≈0.03–0.05 档）——地板若显著高于先验，全臂判读降级为"管线泄漏"（闭式管线任何一段偷看了答案）；明文行正对照列给出段 3 的独立上界（它若低于 0.6 历史水位，段 3 先查）。

## §3 逐段损耗台账（本臂的结构性产出）

逐段登记：段 1 后（v̂ 对真 v 的 cos/逐槽恢复率）、段 2 后（m̂ 对真 memory 行的逐槽探针增量）、段 3 后（端到端 byte_acc）——每一段的损耗单列，四输入列 × 三段全矩阵落盘 JSON。

## §4 纪律与时序

- 判读金规照旧；地板纪律（Q16 方法论入账）升级执行：本臂自带置乱态地板列；
- 成本：缓存张量上的闭式拟合 + 一轮 eval，一天以内；不占训练预算；
- Q18 定稿等本臂落叉（四臂中哪些保留取决于台账指认位置）；
- 收官一次性入册：E 行 + 台账全矩阵 + 落叉判词 + venue 挂钩读数报协作链。
