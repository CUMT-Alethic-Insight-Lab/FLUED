# v3.7 fork 3 立项书：summarizer 保真度改造（段尾写入）

> 2026-08-20 用户裁定执行序落地：硬约束闸门点火（Q10）∥ 非线性段尾探针 → 探针读数落（E89）→ 本立项书冻结。
> 前置证据链：E86 附录 A（接口向量信息集中段首）→ E88 段尾定位包（六臂：memory 行头尾比 5.15× 在进状态机之前已成形，下游近似保形传递——病灶 = summarizer 压缩一级）→ E89 非线性探针（MLP 对线性零超额）。

## 0. 问题陈述

v37 形态下 summarizer（DiT 堆叠 + masked mean pool + FFN）把每段（实测平均 ~25B、上限 64B）压成**一个** d_mem=512 的 memory 向量。实测：段内 slot0-3 的可解码信息（Δacc real−garbage）≈0.44–0.57，slot16-31 只剩 ~0.07–0.10——**段尾字节的信息在编码时刻就没有进入 memory 行**（encode-time LOD 决策的实际形态）。

E89 的判决性读数：2 层 MLP 非线性解码器对线性探针的超额为 **−0.002**（32 个 slot 逐位贴合）——memory 行里不存在"线性拿不到、非线性拿得到"的暗库存。段尾丢失不是读出形态问题，是**写入取舍问题**。

## 1. 靶子（探针读数冻结）

**fork 3 的靶子 = summarizer 的编码目标与容量**——为什么段尾信息没进 memory 行；而不是读出接口形态（本问题维度上读出接口无罪；接口形态墙的判决归 fork 2/Q10 线）。

如实登记的边界：E89 的探针类上限是 2 层 MLP（10M 参数级）；理论上更强的解码器（深网/自回归）可能再多捞。若 fork 3 任何臂把段尾"写进去"了，probe_tail_nonlinear.py 即以同协议复测量作为验收测量。

## 2. 机制假设三分（臂设计按互斥检验构造）

- **H-cap 容量不足**：512 维单向量装不下整段的非冗余内容（段尾被挤出）。
- **H-obj 压力不足**：端到端 codec 损失对段尾的梯度太间接——下游 LM 先验能把段尾字节猜得太好（补全先验地板 0.013–0.036，E88），summarizer 缺乏把段尾存进 memory 的优化动力。
- **H-pool 池化位置盲**：masked mean pool 把段内全部位置洗成袋装均值，位置-内容绑定在池化瞬间丢失，段首集中只是池化后"什么好存存什么"的优化落点。

## 3. 臂设计（单变量逐个消融；全部从头训，仅 S0″ 前端冻结 init 同 canonical）

主网格 = **c 格**（v37.1，v=state——与段尾定位测量同格，剖面口径直接可比；codec 墙现场）。每臂 20K@4096B，配方 = canonical_v37 + `--v-row-source state`（无 cloze，保持与 c 格对照 v37_c_is_v371_20k_ctx4096_20260817 纯净单变量）。

| 臂 | 改动 | 对应假设 | 实现成本 |
|---|---|---|---|
| F0 | 对照（已有 c 格 ckpt，不重跑） | — | 零 |
| F2 | 辅助逐字节重建损失：训练期专用小 decoder 从 memory 行重建段内逐 slot 字节（权重预注册 0.1；推理时拆除，部署形态零变化）。**硬约束（侦察落地）：辅助 decoder 容量封顶（≤2 层/≤10M 参数，与 E89 探针类同档——防 decoder explain-away 假阳性）；判读线只用探针剖面，aux loss 下降一律不作数** | H-obj | 训练器+模块，中等 |
| F3 | mean pool → 4-slot 学习查询注意力池化（每段仍输出单向量：4 个学习 query 注意力池化后 concat 进 FFN）。**硬约束（侦察落地）：query 绑位置锚防 slot collapse（2605.02323，与段首集中同族的槽坍缩是头号内险）；附零参数对照臂 F3z=SGPT 式位置加权 mean（2202.08904，公式实现前核原文）；预注册钉死输出维度口径防与 F1 混淆** | H-pool | summarizer 模块，中等 |
| F1 | `summarizer_dit_layers` 2→4 + `summarizer_hidden` 1024→2048（d_mem=512 不变）。**侦察裁定：降级为配套消融轴**（率失真/IB/posterior collapse 族一致指向"512 维容量远未用尽、容量充足≠会被使用"，单臂基准预期=零收益）；若单臂意外跑赢，强制排查优化/激励混淆 | H-cap | 纯配置 |

判读矩阵（预注册）：
- F2 有效而 F1/F3 无效 → 压力不足是主病（下游先验截胡的又一形态）；
- F1 有效 → 容量墙；F3 有效 → 池化位置盲；
- 多臂有效 → 按效应量排序归因；
- **全无效 → "段尾 LOD 丢弃是当前任务需求下的最优取舍"获强证据，转而审 codec 任务设计本身**（段尾信息对任务无用的假说扶正）。

## 4. 验收判据（预注册，ex-ante，冻结）

**判读金规（撞车侦察 2026-08-20 落地）：判读线只能是探针剖面（E89 协议：岭回归 + 非线性探针复测）；任何训练损失读数（含 aux loss 下降）一律不得作为 fork 3 的成功证据**——F3 的 slot collapse 与 F2 的 decoder explain-away 都会制造"损失在降、病灶不动"的假阳性。F1 若只在段首涨分而段尾不动，按"病灶未动"判负（防段首增益稀释判读）。

1. **主判据（保真度）**：memory 行逐 slot 剖面（E88 同口径：岭回归 real−garbage + 非线性探针复测）头尾比从 5.15× 压到 **< 2.5×**，且 tail Δacc（slot16-31 均值）绝对抬升 **≥ +0.03**；
2. **健康判据（codec 不亏）**：direct_acc / backbone_acc 对 F0 同格对照在噪声带内（±1pp）——防止"保真度上去、任务不动"的装饰性改善；
3. **联动判据**：补全/回读链指标（backbone_acc、E86 附录 A 同协议剖面）方向改善；
4. 全部读数单 seed 初判，阳性臂补第二 seed 确认。

## 5. 边界与纪律

- 本立项只动 summarizer（DiT 堆/池化/训练期辅助目标）；读出接口（fork 2 地盘）、键几何（Q10 闸门地盘）、segmentor（S0″ 冻结）一律不动。
- **AGENTS.md §5 撞车侦察**：已落地 `docs/research/COLLISION_SCOUT_FORK3_SUMMARIZER_FIDELITY_20260820_CN.md`——三臂均无撞车：F2 引 Compressive Transformer（attn-recon）为祖先、ICAE 为正面先例、SAC（2510.08907，"重建≠下游"）为警示；F3 机制件全是标准件（新颖性只能挂考场与判据）；F1 降级（见臂表）。"byte 段单向量+段内位置分辨保真剖面"考场无人占——E86/E89 的逐 slot 探针本身是空档贡献。存疑清单（LLMByte 零命中等 9 项）见侦察报告 §8，引用前需原文复核。
- E 行入册纪律；验收测量工具已就位（`measure_tail_loss_localization.py` 同口径剖面 + `probe_tail_nonlinear.py` 非线性复测，均为分钟级）。
- codec 全覆盖律不动。

## 6. 与在跑闸门的时序

Q10 硬约束闸门（b 格 to_k 白化）在跑（约 2.5h）；fork 3 在其后串行排 GPU（单臂 20K@4096B ≈ 2.4h），点火顺序 **F2 → F3（含 F3z 零参数对照）→ F1（配套消融轴，按需插队）**——先压力后池化后容量：F2 若阳性直接改写 H-obj 主线；F1 依侦察裁定不作独立主臂。
