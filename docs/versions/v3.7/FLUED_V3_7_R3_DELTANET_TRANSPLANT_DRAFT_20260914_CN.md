## §0 立项理由（登记第一条：嫌疑导向读出侧的分解收官链）

- **嫌疑导向读出侧**（分解收官链）：审计四刀把「墙在自创架构件」降为工作假设——粒度刀=五件套并集黑箱；蒸馏刀=S0'' 是规则蒸馏教师、冻结接管，「按内容切」（95% 重组响应在册）≠「切出的单元对检索有用」；字节级刀已被 R2 挡回。UTF-8 分解（2026-09-14 凌晨，双路）：四读出数净超地板质量 **55.6–65.0% 由续字节承载**（续字节地板仅 0.0433，超地板 4.5–5.5×）→ 判决链环②「存储无辜」**保**；R2 账分层封印 119,218 items 逐位一致，**字节碎片逐 token 收益最高**（首碎 +0.16487／续碎 +0.12975＞整字 +0.09840，CI 全排零），最易猜的续字节碎片（术前 NLL 0.92）仍 +0.130——「易猜→零依赖」反向。移植优先级由此定为：**对角护栏 > summarizer 双头构造 > S0'' 段界器**。
- **为什么移植而不是消融**：在我们架构内逐件拆除要动主干接线且件间耦合，残肢不一定是能训的模型；反向移植进健康宿主，每件是**加法或定点替换**，宿主其余部分逐旗标冻结在册（R2 回执 §4 零改造实证可复用），单变量纪律由构造保证，每件 ≈0.5 GPU·h 级——比消融快一个量级。

## §1 体制裁定（本案第一条：基座冻结与变量钉死）

- **基座冻结**：宿主 = **R2 母列同款 DeltaNet-50M**——fla 0.5.1 `DeltaNetForCausalLM`，参数锚 **48,152,896**（唯一解 expand_k=1.0/expand_v=1.0/use_gate=False/use_short_conv=True/intermediate=768，`tools/baselines/deltanet_r2/r2_spec.py` 单源），corpus_v3（sha256 前 16 `ed4ab97810776ce7`），4096B 字节窗，Mistral 32K BPE+BOS 截 2048，**20K 步 from-scratch**，fla 原生 LR 3e-4（warmup 1024／cosine 至 0.1×／betas (0.9,0.95)／wd 0.1／clip 1.0／看门狗 1000，`r2_spec.py` 全套照抄）。**不温启动**：续训引入「先学后装件」第二变量；从零 20K 与母列逐超参同轨，单变量=所移植之件。
- **变量钉死**：每臂**只换一个件**；tokenizer/窗/预算/调度/种子/仪器逐项照抄 R2，「顺手优化」都是体制混杂；效率工时硬上限照 E124 例（2 天，超了先点火再优化）。
- **同卷纪律**：判决仪器与 R2 收官**同款同种子**（500 窗×4 块+池化，选择链 424242／bootstrap 424243，`probe_e122_deltanet_book.py`＋`pool_necessity_blocks.py` 零口径改动）——移植臂不触及 tokenizer/窗/手术语义，与母列共享同窗集同选择链同计分位，逐位可比性由构造成立；母列基尺 **+0.1040 [+0.0951,+0.1125] 直接引用不重跑**（4090 同机同 env，R2 权重与 items 在机）。
- **硬件口径（坑 9 硬件维度）**：全周期同机同 env（远端 4090 24G，fla 0.5.1×tf 5.15.1×torch 2.12.1+cu130，与 R2 收官同一硬件指纹）；读数标指纹，跨硬件只比方向。
- **逃逸口原则沿用**：DeltaNet 纯线性、无注意力层可吸收需求，整模账直接打在状态通道上——移植件毒性若存在，账上必显形（R2 §1 在册）。

## §2 臂定义（三臂单变量；每臂含移植语义等价定义——§9.1–9.3 待用户认可后施工）

### §2.0 移植语义等价的总原则

我们架构内的「件」定义于五件套管线（bytes → byte encoder → segmentor → chunks → summarizer → write head → KDA 状态机 → readout package → backbone → decoder）；DeltaNet 宿主没有这些挂点，移植只能做**语义投影**（件的因果角色保留、结构形态适配）。每臂须交付「语义等价声明」：①件在原架构的因果角色 ②移植构造施工形态（file:line 级）③与原件的不同构点清单（进 §7）④新增参数量。**不同构点未列全＝前置门不过。**

### §2.1 移植甲=对角护栏（读出侧，第一顺位）

- **原件因果角色**：`allowed | diag_eye`（flued/v36/model.py:1844，E124 勘定的自读旁路本体）——backbone 对 store 行轴的一切注意力中，每个查询行**恒可零寻址读自身行**；E124 实测 backbone 重建 99% 由自读承载（全局剔除臂 Δunmasked 仅 +0.003）。原件是**掩码项、零参数**（原位兼有 padded 行防 NaN 职能——本移植不含，DeltaNet 无全掩码行问题）。
- **移植构造（主构造，预注册）**：**恒等自读回声**——每层状态读出处加恒通旁路 `o_t ← o_t + g_l · v_t`，`v_t` = 该层 v 投影输出（use_short_conv 后、β 门控前），`g_l` = 逐层可学标量门 **init 1.0**（全 24 层共 24 个新参数）。语义=「你写进状态的内容免寻址读回」，即对角项的 token 级对应物（我们架构 chunk 行粒度，宿主 token 粒度——粒度差进 §7）；门 init 1.0=通道从第 0 步起全强度可用（对应护栏结构先在性），可学衰减对应 FLUED 对角 softmax 权重的可学性。**零寻址成本**由加法形态保证。
- **登记变体（不并主批）**：(甲-v2) tap 改 β 门控后写入值；(甲-v3) `g_l` 换 `W_echo` 投影（320×320/层，+2.46M，需参数匹配对照）；(甲-v4) 纯恒等无门。主构造选择理由：最忠实于原件「掩码项零参数」性质且参数混杂最小。
- **新增参数**：24（标量门）。**开销系数**：+1–3% 步速（逐元素加+24 标量，算术量可忽略，估计依据=kernel launch 与归一化邻接开销占优；81.5ms 基线 → ~82–84ms）。

### §2.2 移植乙=summarizer 双头构造（写侧摘要，第二顺位）

- **原件因果角色**：`DiTChunkSummarizer`（flued/v36/model.py:391–433；canonical_v37 形态：type=dit／dit_layers=2／pool=qpool 4 位置锚定查询 temp 16.0）——对每块字节段特征做 2 层 DiT 编码+位置锚定池化，经**双头 FFN** 产出 ①memory 头 `ffn` → 段记忆向量（进 write head→KDA 状态内容）②index 头 `index_ffn` → 段索引向量（slm 态，consensus §1.1「summarizer owns the K interface」——寻址以块为粒度）。**嫌疑点=双头构造整体**。
- **移植构造（主构造，预注册）**：**单点摘要+双头全接**——①embedding 后、层栈前，对每个原生 64-token 块的 span 特征过**共享参数** summarizer（DiT2+qpool 构造同构移植，输入域适配宿主 320 维）得 m_c（memory 头）与 k_c（index 头）；②**值侧**：全层栈每层 `v_t ← m_c`（所属块摘要，替换原生 v 投影输出；q/k/β 原生保留）——状态内容粒度从 per-token 变 per-chunk-summary，即「段摘要进状态」的 DeltaNet 对应物；③**地址侧**：块内 64 位置写址方向 `k_t ← k_c` 广播（读侧 q_t 原生）——写侧寻址以块为粒度，对应 index 行语义。头级归因（哪头是凶手）由预注册去消融变体承接：乙判死后加跑 (乙-v2) 仅值侧 / (乙-v3) 仅地址侧（各 ≈0.5 GPU·h，触发条件 §9.5）。
- **新增参数**：DiT2（d=320, heads=5, ffn 768）+qpool+双 FFN ≈ 2–3M 量级（**待施工精算**，约 +5%——混杂在册；参数匹配对照列：乙判死时**自动触发**（与种子加固同级，2026-09-14 用户终审裁定；不并主批，归因「构造毒性 vs 参数量」）。**开销系数**：+6–10% 步速（summarizer 单点 ≈ 2 个 layer-equivalent 前向 ≈ 原生 24 层的 ~8% FLOPs，显存受限工况墙钟折减；依据=R2 实测 81.5ms/24 层标定 → ~86–89ms）。
- **不同构点预告**（§7 详）：输入模态（byte-encoder 384 维 vs token embedding 320 维——**byte encoder 不入件**，件边界=池化+双头构造组）；span 粒度（64 token≈161B vs 我们 24B/块，qpool 位置锚运行点漂移）；DeltaNet 状态无行结构，m_c 值侧广播=语义投影非结构移植。

### §2.3 移植丙=S0'' 段界器（写侧段界，第三顺位；**移植语义是三臂中最难的，见 §9.3**）

- **原件因果角色**：S0''=规则蒸馏教师段界器，冻结接管（canonical_v37；权重 `s0pp_pro_v4_sft_20260805/latest.pt`；架构=byte encoder 3 层+segmentor 9×DiTStyleBlock+LayerNorm/Linear 头，boundary_mode=dynamic/temp 0.15，flued/v36/model.py:2431–2434；在册运行点 ~24B/块、172.7 块/窗）。**独立于宿主干网**：只吃原始字节窗、吐切点，无需域适配。
- **硬问题（起草期已勘定，须向用户亮明）**：**DeltaNet 的分块（`wy_fast.py:226 BT=64`）是计算铺瓦（tiling）不是语义单元**——chunked delta rule 是线性递归的代数精确重排，铺瓦粒度不改变算出的函数（逐位差仅 fp 结合序）。我们架构内段界器的毒性经「变长块→逐块状态行→摘要→寻址」链条表达；纯线性宿主**没有这些挂点**，直接换 BT=64 在数学上是 no-op。移植语义须在下列三者显式选定（§9.3）：
  - **(c1) 变长铺瓦臂（主构造建议）**：按 S0'' 切点做变长 WY 铺瓦（预期 ≈172.7 段/窗——同字节流同段界器，E124 门②在册数、施工直测复核）。**预注册判词预期=不杀**（函数恒等）——科学价值=把「铺瓦粒度不影响训练动力学」从声明升级为实验事实（E123 体制分岔教训：逐位差可分盆，此臂非空洞）；若杀=「铺瓦敏感性」真发现，归因改写。
  - **(c2) 切点语义注入（超出单变量移植范畴，需用户裁定另立项）**：S0'' 切点驱动状态语义（如切点 β 重写=段界处写入刷新）。这是我们架构段界器毒性的真挂点，但属**发明新机制**，本草案不展开。
  - **(c3) 评测侧对齐（不作为臂）**：模型不动、仪器跨段定义对齐 S0'' 切点——零训练、母列 ckpt 可跑（小时级），登记为丙的**附属读数**（机制注记不判负正，不改主判决口径以免破同卷）。
- **丙的前置特有件（零训练）**：**函数恒等对拍**——R2 母列 20K ckpt 上同窗对拍原生 BT=64 vs 变长铺瓦的 NLL（冻结容差，E121 逐位/容差双档先例）——对拍不过=实现有 bug，不许点火。**实现路径待定**（fla 0.5.1 `chunk_delta_rule` 是否暴露 initial_state/final_state 接口待核；备选=自写 masked-tile 核，工时风险 1–2 天）。**开销系数**：×1.3–2.5 步速（同 FLOPs 下铺瓦 26→~172 段，state I/O 与 kernel launch 增；**待实现路径定型后精算，报价回执不过不点火**）。

## §7 诚实边界与外推

- **判词约束范围**：每格判词=「该件在 DeltaNet-50M×本体制内的毒性」，**不自动外推回我们架构**——「乙杀」证明双头构造足以杀死健康宿主，不证明它在我们架构内是 E124 级主凶（在架定责仍需 E125 式改造臂承接）；「不杀」也不洗清该件在我们架构内的嫌疑（宿主缺失态可能必需）。两向都不越级，是本案与 E125 的分工边界。
- **非同构清单汇总**（判读引用必带）：甲=粒度差+宿主天然局部通道；乙=输入域/qpool 运行点/参数量+5%/无行结构；丙=函数恒等预期+实现路径耦合。**语义等价声明未列全的不同构点，事后发现即降该臂判词一档（判词→注记）重审。**
- **母列基尺引用边界**：+0.1040 引用带全限定（规模×预算×体制）；DeltaNet-1.3B +0.2806 只作方向锚（坑 9），本案不新增依赖。
- **丙 (c1) 预期不杀不是无效臂**：最便宜的可证伪件之一；兑现=排空「计算铺瓦粒度」嫌疑维度（蒸馏刀残余形态），使 (c2) 立项讨论在干净前提下进行。
- **兜底格的范式含义**：格 8 兑现时「移植定责」方法论本身受质疑——措辞降级令（工作假设不进摘要）自动延续，直至未移植件定责有果。
