## §1 问题与判读对象

E121 的「不确定」格有两个观测等价的解释，本账是它们的分辨仪：

- **解释 A（需求侧误判）**：D1 选中的稀有续尾位，其目标字节**并不需要**跨段内容——窗内/先验（形态、拼写、模板续写）即可覆盖。稀有度只是「先验猜不中这个字节」的代理，不等于「只有跨段检索能拿到」。若此，E121 的「剂量够但消费未出」是误判，真相是**剂量没打在黑板上**；
- **解释 B（动力学/接口侧）**：位点确实需要跨段内容，但回路没形成（E120 墙的延续）。若此，修需求侧没用，该修接口（H-DEMAND-GATE）或训练形态。

判读对象 = D1 选中位（w2 选择图，seed42 窗流，分位数档最稀有 20%，L=6/T=3）对**源 L-gram 内容**的依赖量。

## §2 架构事实基础（2026-09-06 只读核实，agent-172，全部 file:line 在案）

1. **decoder/codec 无任何逐字节直读路径**——审计提案的 (c) 臂（「屏蔽 decoder 窗内直读源 chunk」）**结构性无对象**，作废；
2. 跨段信息到达目标位 NLL 仅两条路径：**路径 A**=encoder 全窗注意力把源内容隐式混入目标 chunk 自己的 memory 行（不可手术剥离——任何源侧遮蔽都会连锁改变 byte_states 与分段时刻表）；**路径 B**=backbone block1 对更早 chunk store 行的因果 cross-read（**可手术**：`store_block` 掩码 `flued/v36/model.py:1705,1766-1767`，Q15 仪器族现成用法 `train_v36_s1.py:1331`、`probe_burst_route_q15.py:158`；行置乱 `_patch_state_zero` 同款）；
3. **推论（写进机制章的口径修正）**：本架构下脸③「答案只经状态通道可达」的真实含义不是「窗内 vs 状态通道」二分——一切信息都经压缩行——而是「**隐式混入 own-row（受压缩粒度/容量限制）vs 显式行索引（可取回逐字内容）**」。必要性账的 b1/b2 分解就是这两个层次的分离测量。

## §3 仪器设计

**基座（冻结）**：主基座 = d 格 25b（`v37ks_d_sm_q15_circuit_20k_ctx4096_20260825b`，在役最强、E120 同基座）；副基座 = a 格 w1 10K（`v37ks_a_d1_w1_10k_ctx4096_20260904`，与 D1 同网格的弱模型下界）。装载走 `probe_oracle_write_verdict.load_model` 骨架（resolved_config→build_model→strict→硬冻结，:101-119）——坑 8 同族键（`seed_source=k`/`k_row_source=v_row_source=state`/`summarizer_pool=qpool`/`backbone_mode=slm`）以 resolved_config 显式携带为准，脚本侧全键断言，禁止 getattr 兜底。

**条件臂**（同一批窗，同一冻结基座，逐位 NLL 全 fp32 无 autocast）：

| 臂 | 手术 | 测什么 |
|---|---|---|
| (a) 完整窗 | 无 | 基线 |
| (b1) 外科替换 | 源 L-gram 出现处替换为**同长度、同 UTF-8 续字节结构、同为稀有表内**的另一 gram | **必要性总量**：目标位对源内容的全部依赖（路径 A+B 合计） |
| (b2) 行手术 | 源 chunk 的 store 行置乱（permute 行内容，保留行存在性） | **显式索引路径**：目标位经路径 B 对源行内容的依赖 |

**对照与卫生**：
- 同窗未选中位（等量随机抽样）作对照位——两条件差值在选中位 vs 对照位的**对比**是主判读量（替换本身的 surprisal 位移由对照组吸收）；
- b1 的**分段漂移检查**：替换前后 `_cuts` 对比，目标位上游分段漂移的窗剔除并报告剔除率（预期个位数百分比）；
- 任务注入全关：`--burst-prob 0`、cloze/retrieval 同理；eval mask 命中位剔除（mask 纪律照 `build_masks`，:143-158）；
- 位点映射：D1 扫描器同源（`cross_chunk_occurrences` 选择图）+ **d 格累积网格的字节位→(chunk,slot) 映射重写**（`_d1_build_weight_map` 在累积网格响亮报错 `train_v36_s1.py:2962-2967`，须按 `make_cumulative_retention_targets` 语义重映射）；
- 逐位 NLL：`F.cross_entropy(reduction="none")`（先例 `probe_v36_cbiu_anchors.py:78`）；判读只在 CUDA 线（kda_impl=fla，CPU 强切 torch 有微差）。

**样本量**：500 窗（seed42+9999 eval 流，与 D1 选择图同源窗流——坑 9 同卷纪律），每窗全部选中位（~455–510）+ 等量对照位。三臂×两基座 ≈ 单卡 1–2 小时级。

## §4 判读表（冻结 v1.0：主判据=选中位 vs 对照位的 b1 差值对比；唯一自由数=1.0 nat，弱/无分界=统计判据）

主量：ΔNLLᵢ = NLL(b) − NLL(a)，逐位；主判读 = mean ΔNLL_b1(选中位) − mean ΔNLL_b1(对照位)，bootstrap 95% CI（窗级重抽样）。逐位 ΔNLL 为冻结模型确定性前向读数，无估计噪声，统计性全由抽样端 bootstrap 承担。

| 格 | 读数 | 判词 | 行动出口 |
|---|---|---|---|
| 必要性实存（强） | 对比 CI 不含 0 **且** 选中位差值 ≥ 1.0 nat | **剂量打在黑板上**——E121 解释 B 成立，墙在动力学/接口 | H-DEMAND-GATE oracle 需求探针（零训练）排下一；接口臂预注册 |
| 必要性实存（弱） | 对比 CI 不含 0 但 < 1.0 nat | 剂量部分在板 | b2 分层判读 + 第六脸小臂（先验剥夺）与接口臂双排 |
| 剂量未落 | 对比 CI 含 0 | **E121 改判需求侧误判**——稀有度过滤不是跨段必要性代理 | 第六脸需求重设计优先于一切架构臂；D1 稀有档口径复盘 |
| 反常 | 选中位差值 < 对照位 | 仪器 bug 或选择图口径错 | 停，转口径审计 |

**有效跨段密度换算**（次判读，对齐密度账）：强命中位（ΔNLL_b1 ≥ 1.0 nat）计数/窗 = 有效黑板密度；**落点线 50%**（= 密度账最严口径 54.8 字节/窗 ÷ D1 实际监督 ~110 字节/窗）——强命中率低于 50% 时，有效密度已跌破当初给 E121 放行的那个数，**算术关在修正后的密度上自己都不过**；且错配剂量不是中性而是反噬：w=2 加权在先验本可覆盖的位置=给竞争解加权训练（脸⑤反面）。

**b2 分层读法**（不进主判读表，只作机制章素材）：ΔNLL_b2 ≈ ΔNLL_b1 → 冻结模型的依赖走显式行索引；ΔNLL_b2 ≪ ΔNLL_b1 → 依赖被 encoder 隐式混入 own-row（容量/粒度受限）——后者直接喂 H-DEMAND-GATE 的设计动机（显式索引还没被用起来）。

## §7 诚实边界

- NLL 敏感性是信息使用的**下界**：基座能力不足会低估必要性——主基座选 25b 缓解但不消除；副基座（a w1 10K）的读数只作「同网格下界」注记；
- b1 替换即使三匹配仍是分布外操作——对照组吸收主效应，残余污染如实注记；
- 本账答「剂量是否落在需要跨段内容的位置」，不答「回路能否形成」（后者归后续训练臂）；「需要跨段内容」≠「需要显式行索引」（b2 才碰这层，且只测现状模型非架构可达性）；
- E119/E120 已证读出链可取回行内容（仪器级 0.596）——「压缩行能否携带逐字内容」不是本账的开放问题。
